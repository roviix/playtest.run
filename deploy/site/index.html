One command puts the build you have right now in front of
other people, and tells you how it went.

For people making small things with AI, game jam entrants, indie developers, creative coders. What you built runs in a browser; the audience is specific people — friends, testers, judges, students.

playtest ./dist                # upload an export directory → https://xxx.playtest.run and a QR code
playtest 5173                  # hand out the dev server already running here, same kind of link
playtest ./dist --backend 3000 # static files uploaded, /api and WebSockets tunnelled to your backend
  • Testers do not sign up or install anything
  • Scan the QR code and play on a phone
  • No account needed: an Anonymous link lasts 24 hours
  • We serve your files, we never run your code

What a tester sees

1
First a page that says “<author> invites you to test Your Title · v7” with a Start button. That one click unlocks browser audio, and it is where the session begins.
2
Then the project itself. .wasm, pre-compressed .br, the cross-origin isolation Godot 4 needs, range requests — the places engine exports usually turn into a white screen are already set up at the edge.
3
What the Developer Console gives you is not a dashboard, it is a roster: how many opened it, how many got into the game, how long they stayed, which device reported which error, and what they said.

Where this stands

Working today: uploads, tunnels, the hybrid static-plus-backend mode, the Door page, the roster, the invite card (playtest card writes <title>-invite.png), the optional playtest.js (one <script src="/_playtest/sdk.js"></script> line gives you JS errors, load timing, custom events and a feedback button), Plaza (--public and --seats), and version rollback.

Landed recently, not yet verified on anyone else's machine: sign-in (playtest login; projects you published before signing in move into your account and stop expiring after 24 hours). Not built yet: picking your own link name, passwords and invite lists, custom domains. The CLI says so whenever it cannot do something.

You do not need an account: every run gives you an Anonymous link that lasts 24 hours, and pasting the token from ~/.config/playtest/config.json into the Developer Console shows you the results.

Install

One binary per platform: macOS (Apple Silicon and Intel), Linux (x86_64 and arm64) and Windows. The current release is v0.4.0, and the source is public at github.com/roviix/playtest.run.

# macOS / Linux: one line, installs to ~/.local/bin
curl -fsSL https://playtest.run/install.sh | bash
cd your-export-directory && playtest .

On Windows, or if you would rather do it by hand, download the archive for your platform from GitHub Releases and put playtest on your PATH. The binaries are not signed or notarised yet; if macOS blocks the first run, allow it once under System Settings → Privacy & Security.

Everything a tester sees lives on *.playtest.run; sign-in, tokens and the Developer Console exist only on this domain. We never run your code — we serve files and forward connections. We do not record tester IP addresses and we do not collect location. Data is kept for 90 days by default.
