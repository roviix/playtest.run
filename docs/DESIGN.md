# playtest · 产品推演与设计

> 把正在做的作品拿出来，让别人体验、说一句有用的话，再带着他们走到下一版。

> 本文是唯一产品定义，描述我们要交付什么，不是已上线能力清单。每个结论都要能回答「为什么不是另一个」；方向变了直接重写，不留 changelog。
> 市场调研的证据在 `docs/research/`，真机记录在 `docs/spikes/`。没有相应真机记录的能力，不因写进本文就成为「已支持」。
> `docs/whiteboard.html` 是结构草图；未同步的图、README、帮助与界面不得反过来定义产品。

## 0. 结论

先读这一节，其余各节是它的出处。

1. **起点是「做出来了，却没有人认真看，也留不住下一版的观众」。** 网页游戏里的「没人玩」是已有研究的起点，不是所有创作者需求已经被验证的证据。我们服务的是愿意拿出作品、得到反馈、继续创作的人；游戏、工具、文章、视频都可能有这个时刻。价值不止是得到一个地址，而是有人实际体验、说出具体问题、下一版还愿意回来。
2. **playtest 是一种以作品为中心的 build in public 方式，也是服务这些创作者的产品。** 在这里，公开创作不是每天发一条「我很努力」的动态，而是让人接触这版真实作品、知道作者想弄清什么、看见下一版的变化。理念落在发布、版本说明、反馈与回访里，不另建一套社交动态系统（§1.5）。不要求开源、不要求晒收入，也不要求所有创作过程都公开。
3. **作品不按「是不是游戏」划边界。** 网页作品、文章、视频都是一等作品，可以独立发布、分享、收反馈和被关注；不需要把文章或短片伪装成游戏的附件。第一批格式有明确上限（§3.16），不承诺任意文件都能变成好用的作品。完成的作品也可以留下，不要求作者永远处于测试或日更状态。
4. **三个环仍是产品骨架。** **邀请环**：作品链接与邀请卡把人带进来；**回访环**：具体反馈帮助作者迭代，版本说明与自愿关注把人带到下一版；**注意力环**：广场、合集与创作挑战让人发现别的作品。传输是供给能力，反馈是继续使用的理由，回访是公开创作能积累而不总从零开始的原因。公开文章的读者和游戏的玩家不自动是同一群人，跨类型发现需要实际运营验证。
5. **体验者首次零门槛，留下与公开都自愿。** 玩、用、读、看都不要求登录或安装，不因增加作品类型而多一道必经跳转。名字、关注、反馈不挡内容。作者默认只拿到可分享的链接，不自动上广场；不公开收录不等于私密，限制访问仍走明确的权限设置。公开作品也不自动公开历史、反馈、源码或邮箱。
6. **邀请卡是分发材料，作品是积累单位。** 卡的口吻是「某某邀请你试玩 / 体验 / 阅读 / 观看」，不是「你获得了」；它帮助群里的接收者判断是什么、谁发的、要不要点。卡按需下载，不污染发布目录，不拖慢链接返回。更新同一作品继续使用同一分享地址，不为每版重建观众关系。
7. **广场是创作与反馈的俱乐部，不是无限消费的信息流。** 只放作者主动公开的作品，保留按时间浏览、类型识别、合集与挑战，推广透明限位。先让一群愿意体验和反馈的人持续回来，不以百万 MAU 或无限播放为目标；小规模也不免除治理责任。关注作品看迭代，关注合集看新作品，关注广场看周报，各自说明触发什么，不顺带订阅。
8. **收钱卖的是「被看见」和「持续、认真地迭代」，不是无限存储。** 推广卖明确标识的展示机会，不保证人数或好评；Pro 卖稳定身份、受控分享、版本与结果留存。免费档硬上限、不产生账单，体验者不为打开作品付钱。文章与视频作者的付费意愿尚待实际使用证明，不把游戏测试预算直接外推过去。
9. **安全与信任不随形态放宽。** 服务端不运行用户代码；免费额度与每作品每小时熔断不撤；原有网页文件不注入、不改写；文章阅读器与视频播放器是明确选择的交付方式，不伪装成原文件；平台根域不执行作者脚本、作品使用独立源。打开不冒充看完，页面活动不冒充理解，署名与创作过程是作者自述，不是平台认证。
10. **第一批用户在大陆，边缘在香港，全球可用是底线；微信是分发渠道，不是浏览渠道。** 卡片和群在微信里传播，广场在系统浏览器和别的 App 里活。越火越容易被微信整域拦截是这条路上唯一没法用产品设计消掉的风险（§5），选择承担。
11. **开源不变**（§7）。CLI 与 SDK 宽松许可，边缘与控制面 AGPL 且可自托管；托管服务是生意。
12. **S3 是作品物料的目标生产主存储，本地物料目录只做缓存与临时文件。** 作品原件、配套资源、衍生展示产物与清单进私有对象存储；账号、权限、关注与反馈继续在关系库，其数据库磁盘另行管理。源站不直接暴露给体验者，访问仍受边缘的权限和额度约束。迁移顺序与真实状态见 §4.2，不用目标架构冒充上线事实。
13. **方向完整，交付分批，承诺逐项验收。** 先完成真实 S3 上的现有网页路径，再交付文章、视频与公开迭代闭环。健康指标用于改进，不设机械的生死线；但任何没有相应真机记录的格式或存储路径都不能写成已支持（§8）。

**为什么不是另一个产品。** 不是仅替文件找一个网址的托管服务，也不是追求观看时长的内容平台，更不是要求创作者经营人设的社交网络。我们让真实作品、具体反馈和下一次迭代接在一起；对「努力带来合适的人」负责，对无法保证的流量和认可不作保证。取舍集中在 §9。

### 0.1 收敛：同一个人的发现与创作

**产品与地址。** 平台统一在 `playtest.run`：广场、关注、账号、发布说明、管理和文档共享导航与登录状态，不再让人往返两个品牌地址。作品原件仍由 `<slug>.playtest.run` 独立源交付，本轮不增加运行域，不保留旧域兼容或旧身份迁移。选择单域是减少 M2／M3b／M3c 的认知与回程成本；接受同站子域带来的额外防护责任，不声称等价于独立可注册域隔离。

**导航按任务而不是人群划分。** 常驻入口是广场、关注、我的作品、我的合集。广场内用直接可见的「作品／合集」页签切换；挑战是合集的一种，不新增一级频道。管理作品与组织合集的动作不同，两个管理入口分开。发布是行动按钮，文档与账号是辅助入口。作品邀请页保持专注，不强塞工作区侧栏；收到链接仍直接接触作品，无登录、安装或新必经跳转。

**一个账号，多种验证方式。** 邮箱验证与 GitHub 都进入长期账号体系，不按体验者／创作者拆账号，不要求切换角色。作品归属与合集组织权按资源授权，通知渠道与订阅意愿独立。首次邮箱验证建立最小账号，之后恢复同一账号；登录不顺带关注周报，发布不追溯公开匿名反馈或邮箱。浏览器通知不是账号。邮箱与 GitHub 关联必须由已登录用户明确发起并完成另一方式的验证，不按昵称或邮箱文本静默归并。匿名首次发布继续可用，接管须同时证明原发布凭据。

**凭据与回程。** 网页使用可撤销、到期的 HttpOnly host-only 会话，不在 localStorage 保存发布令牌；CLI／助手令牌与网页会话分开。GitHub OAuth 绑定发起浏览器与一次性 state。登录后返回原页面或原投稿意图，不返回空白后台；退出清理当前会话，不删除作品。访问令牌只在账号的开发者设置中主动创建，普通登录界面不要求粘贴令牌。

**防护不是可选样式。** HTTPS 使用 `__Host-pt_session; Secure; HttpOnly; Path=/; SameSite=Lax`，没有 Domain；本机 HTTP 使用 host-only `pt_session`。API 和根域表单对携带网页会话的写请求校验精确 Origin，拒绝作品子域代操作；代理只在根域暴露平台 API，作品源不转发平台会话，也不能设置平台或父域 Cookie。公开页面不缓存个人状态，不运行作者脚本。平台会话失效、邮件未开通或服务故障都给真实可恢复的提示。

**验收按完整路径。** 未登录体验、邮箱首次登录与再次登录、GitHub 登录与退出、跨广场／关注／管理保持同一账号、作品关注、挑战投稿回程、发布与匿名接管、窄屏键盘和焦点、子域伪造写请求与凭据过滤，都需要对应测试与浏览器记录。线上部署与真实邮件／OAuth 往返分别记录；测试替身不冒充外部服务验收。当前允许清空本地及线上产品数据，不以兼容旧状态增加界面和逻辑。

## 1. 起点：人和时刻

### 1.1 谁

供给侧统称**创作者**。开发者仍是第一批用户，但不再是唯一身份；是否用 AI、是否写代码、是否自称 build in public 都不是准入条件。

- **用 AI 做东西的人与独立开发者。** 小工具、产品原型、Phaser 小游戏、Three.js 场景、本地正在运行的服务。手上已有目录或端口，可能通过助手发布，希望别人实际用一次，而不只给截图点个赞。
- **游戏、创意编码与互动体验作者。** Game Jam、Godot / Unity / Cocos 等 Web 导出物、shader、生成艺术、数据可视化、课堂演示。既有引擎与隧道体验不因增加内容类型而降级。
- **写作者与视频创作者。** 手上有文章及配图、短片、演示视频，希望有人指出哪里难懂、节奏哪里不合适，并愿意再看改稿。文章与视频可以是创作本身，也可以讲述另一个作品的过程。
- **公开学习与持续创作的人。** 通过一系列作品记录学习、参加创作挑战、展示尝试和修正的人。今天发布、明天体验别人的作品是我们希望形成的行为，不强制互评、不用刷反馈换曝光。

共同点：已有一件能让别人体验、阅读或观看的作品，想要「现在给你看，再听一句具体的话」，不必等正式上架或先拥有粉丝。优先服务已经在本地工具或 AI 助手里创作的人，CLI / MCP 是这批人的入口，不把「作者必须会终端」误说成全人群零门槛；纯浏览器作者的发布摩擦仍需另行验证。

需求侧统称**体验者**，包含玩家、使用者、读者与观众：

- 作者的朋友、同行、潜在用户、同题创作者、被一张邀请卡吸引的人。他们首先想接触作品，不是注册账号或成为免费劳动力；反馈是邀请，不是访问成本。对有兴趣的作品，他们可以自愿知道下一版来了。

**称呼约定。** 通用界面用「创作者 / 作品 / 反馈 / 更新」；游戏用「试玩」，工具与互动页面用「体验」，文章用「阅读」，视频用「观看」。本文保留的「玩家域」「平台根域」是既有安全边界的名字，适用于所有形态，不因此新增域名或身份系统。

### 1.2 创作者的时刻

| 时刻 | 现在怎么做 | 哪里疼 |
| --- | --- | --- |
| **M1 · 在另一台设备上看一下**（创作中，自己一个人） | 本地端口、文件互传、把文章或视频发给自己 | 网络不通、手机排版或播放不一致，不想先搭一套部署流程；网页能力还可能需要 HTTPS |
| **M2 · 现在发给朋友看**（几个人，几分钟） | zip、网盘、临时部署、导出截图 | 对方要下载或安装、找不到正文、等构建；一次分享被工具切碎，作品本身没有被接触 |
| **M2b · 让对方敢点开、知道怎么看** | 一条裸链接或没有上下文的附件 | 不知道是谁、是游戏还是文章、这版是什么、作者想听什么；愿意点开的人也可能预期错误 |
| **M3 · 找一批人给具体反馈**（5–50 人，几天） | 群聊、表单、审稿消息、视频时间点截图 | 反馈对不上版本，不知道问题发生在哪个设备或哪段内容；只有「不错」，不能帮助下一次修改 |
| **M3b · 手上有作品，没有观众**（一个人，反复发生） | 发群、发动态、发求测帖 | 每次解释上下文，帖子沉下去就结束；没人实际体验，曝光和反馈是两回事 |
| **M3c · 下一版还有人来**（第二版、第三版） | 再发一次，重新找人 | 上一版的人找不回来，对方不知道改了什么；同一作品不能积累观众与信任 |
| **M3d · 让后来的人看懂创作过程**（公开创作、复盘） | 到处翻进度帖、重新整理截图和链接 | 作品、改动与反馈分散，后来者只看见终稿；公开过程又怕误公开草稿、私密反馈或原始资料 |
| **M4 · 正式发行与内容变现** | 商店、发行平台、付费内容平台 | 交易、订阅售卖与正式分发不是我们的主线；已完成作品仍可按本产品配额留在这里 |
| **M5 · 带后端 / 联机的版本给人试** | 部署服务器；或 ngrok / frp | 静态托管做不到；ngrok 在大陆不稳；联机测试真正的瓶颈是让四个人同时在线 |

### 1.3 体验者的时刻

| 时刻 | 现在 | 哪里疼 |
| --- | --- | --- |
| **P1 · 收到一张卡** | 群里的链接或附件 | 不知道谁做的、该玩还是该读、作者想听什么 |
| **P2 · 直接接触作品** | 登录、下载、跳转、白屏、视频打不开 | 每多一道门槛都偏离这次邀请；阅读不应被播放器或注册页挡住 |
| **P3 · 想说一句话或留下来** | 关掉页面，或回群里描述「刚才那里」 | 找不到对应版本，想知道更新又不想注册；也有只想看、不想反馈的人 |
| **P4 · 再来与看过程** | 新旧链接和进度帖散落各处 | 不知道这版改了什么、上次的问题有没有变化、怎样继续看同一次创作 |

### 1.4 从时刻推出来的三件事

1. **时刻决定交付方式，不让用户先懂托管。** 目录、文章和视频走上传；正在运行的网页与后端保留隧道。作者交付原件，平台提供被明确选择的阅读或播放方式；同一种作品继续用同一个身份更新，不为每种格式复制一套发布与关注系统。
2. **首次零门槛，之后自愿留下。** P2 决定了玩、用、读、看都不要求登录或安装。文章在作品邀请函同页可读，视频同页可点播，网页保留原有纯净子域直达；不多加一次「进入阅读器 / 播放器」跳转。反馈、留名、关注与公开历史都不成为必经步骤。
3. **作品让过程有依据，回访让过程能积累。** M3b / M3c 需要合适的人，M3d 需要能看懂的连续性。邀请卡、版本说明、具体反馈、关注与合集已经能承接这条路；不必先做一套个人动态、打卡或粉丝榜。

### 1.5 Build in public：实践、产品与选择权

在 playtest 中，build in public 的操作定义是：**拿出可接触的作品 → 说明这版在尝试什么、想听什么 → 收到具体反馈 → 发布下一版并说明变化 → 让愿意的人继续跟进。** 它可以服务软件开发，也可以服务写作、短片与公开学习；我们提供一种做法，不宣称垄断这个理念。

- **公开真实作品，而不只播报进度。** 文章和视频本身可以是作品；一段复杂过程也可以写成独立文章。短更新直接用版本说明，长内容与其他作品用已有合集组织（§3.7、§3.15），不为每次进度再造「动态」。这让 M2 与 M3d 更短。
- **反馈应当能进入下一版。** 用作者自己的更新说明解释变化，可提及获得允许公开的反馈；不自动归因、不生成「用户驱动迭代」的功劳叙事。先让 M3 的反馈有上下文，再看 M3c 是否真的发生。
- **公开程度由作者决定。** 分享链接、收录广场、公开版本说明、公开反馈分别表达不同意图；选择一个不自动打开其他项。源码、提示词、原始素材、收入、失败经历、日更频率都不是义务。作品可先私下分享再主动公开，也可一直受控分享。
- **不要求经营个人品牌。** 首批以作品关注和合集组织服务持续创作，不把作者主页、关注人、跨平台自动发帖或粉丝增长工具设为前提。原来的社群仍可以是对话场所，我们不强迫作者搬家。
- **不把公开等同于增长已成立。** 不承诺有人看、人人给反馈或多种作品自然共享受众；按形态观察首次有效反馈、再次发布与再次访问（§8.5）。既有网页游戏研究是起点，写作者和视频作者的需求要各自取得证据。

外部理念参考：[Buffer 对公开过程与分享边界的介绍](https://buffer.com/resources/internet-transparency/)；本节是我们的产品取舍，不把别人的实践或结果当成自己的验证。

## 2. 市面上已经有什么

2026-09-07 查过一遍，同日用 13 条调研线复核（`docs/research/`）。以下是当时围绕网页游戏与交付工具的调研，不是当前全市场的穷尽比较；其中价格、可用性和供应商状态需在实际采用前复核。所有「几步 / 多久」除 `docs/research/2026-09-07-hands-on-tunnels.md` 外都是从文档推的，不是实测。文章、视频与 build in public 的人群选择是新范围，不能借这份材料宣称已经验证。

### 2.1 六类现有解法

| 类 | 谁 | 做得好 | 缺的 |
| --- | --- | --- | --- |
| **上传 Web 构建拿链接** | itch.io（butler）、Unity Play、The Gaming Nest、Final Parsec、**Surge**、Netlify Drop、tiiny.host、SIMMER（2025-04 死于 DDoS 账单） | 红海：免登录出链接是行业常态、有 CLI 或引擎插件、有版本回滚 | 全在境外——itch 在大陆整域屏蔽，`vercel.app` 大多被屏蔽；**没有一家在上传那一刻告诉你为什么跑不起来**；只有 itch 做真增量但后端 processing 最长 30 分钟；不做隧道；不做结果；**没有一家把「谁来玩」当自己的事** |
| **AI 单文件 HTML 托管** | Clawcade、AIGameShare、rendrd（两家有 MCP server）、ArcadeLab、localgames.fun；腾讯 EdgeOne Pages / Makers | 零门槛、单文件、agent 直接发布——打的正是 §1.1 第一类人 | 不碰引擎导出物；EdgeOne 大陆节点要备案、平台域名在大陆只给 3 小时预览链接；有的有画廊页，但玩家不能关注、开发者拿不到下一版的回访 |
| **Playtest 结果** | 按录像分钟卖（Playset、Playcocola）；按 AI credit / 席位卖（Playloop、Bugnet、LoopKit、PGPT）；按「帮你找到人」卖（The Playtest、FirstLook、Antidote、PlaytestCloud） | 「玩家零门槛」是共识；截图标配；**这一类有一半产品的价值在「帮你找到人」**，价格 $115–2,825 / 月 | 全类目没有隧道；**没有一家以命令行为入口**；没有一家做交付；找人那一半全是人工招募的高价服务，没有一个是「你的玩家自己留下来」 |
| **通用隧道（全球）** | ngrok、Cloudflare Tunnel、bore、zrok、pinggy、localhost.run；围绕 AI 编程新出的 tunr、uplink | 「分享 localhost」被做透 | 依赖境外托管网络，大陆连接差；**没有一个会补游戏响应头**；访客侧中间页是例外；没有上传路径 |
| **通用隧道（大陆）** | cpolar、natapp、花生壳、樱花 frp、飞鸽 | 大陆节点 | 免费档 0.5–10 Mbps，随机地址、签到、实名；无上传、无结果、无游戏感 |
| **正式分发** | Steam Playtest、TestFlight、微信 / 抖音小游戏、TapTap 篝火测试 | 平台，有玩家 | 是 M4 不是 M2 / M3；小游戏体验版要后台加体验成员、正式版要审核与备案 |

两个真实的替代品不在表里：录个视频发 B 站（免费、稳定、绕开一切兼容问题，代价是失去交互和行为反馈）；AI 编辑器内置分享（TRAE 已有产物链接，Lovable / bolt / v0 内建发布——GitHub Spark 2026-08 关停的教训是强制登录杀死传播）。

### 2.2 离我们最近的几家，以及我们不一样的地方

- **itch.io**：是这个位置上真正的在位者——有画廊、有 follow、有 jam、有 devlog；但大陆整域屏蔽，且它是商店（支付、成人内容、支付商压力）。我们和它的差：一条命令、大陆可达、对游戏有感的边缘、点名册式的结果、不卖游戏只卖被看见。
- **Poki / CrazyGames**：证明「有玩家的地方可以卖 playtest」——Poki Playtesting 靠 1 亿 MAU、CrazyGames 的 Basic Launch 靠 5,000 万 MAU。我们不需要那个量：几千个回访的试玩者就足够改变每个开发者的第二版。
- **Surge**：形状最像上传路径（`surge ./dir`、免登录、不可变版本、回滚、统计）。差在游戏响应头、门禁页、结果、香港、同一条命令走隧道，以及它没有观众。
- **tunr 与 uplink**：隧道侧认真的对手，已在卖反馈组件和 MCP。差别是它们不管游戏、没有上传、境外，也没有观众。它们开源免费，决定了我们也必须是（§7）。
- **Clawcade 与 EdgeOne**：AI 人群与大陆两侧的相邻对手，各占一半。Clawcade 有 agent 入口没有引擎导出物；EdgeOne 有大陆节点但要备案、默认域在大陆只给 3 小时。
- **Playset 等「结果」类**：没有一家做交付、没有一家以 CLI 为入口；「帮你找到人」那一半靶向发行商预算，$115 起步。我们把「找到人」做成玩家自己留下来，边际成本接近零。

### 2.3 缺口与风险

**我们的机会假设**：把交付、版本、具体反馈、自愿关注与发现放在同一个作品身份上，让公开创作少一次整理和重新找人。这不是「没人做过内容发布」，也不以「没有竞争对手」作前提。社交平台能讲过程，内容平台能承载文章和视频，代码仓库能记录代码变化；我们选择让接收者直接接触作品，并把反馈带到下一版，而不是复制这些平台的全部功能。

**风险**：一个公开的地方意味着内容审核、举报处置、排序公平和持续运营（§4.8、§5）。文章、视频会扩大版权、隐私与带宽的处置范围；不运行代码不会消除这些风险。技术上统一三种类型，不等于有同一群观众；没有运营和合适的作者供给，格式越多也可能只是空页面越多。扩范围不同时扩成社交网络、编辑器或无限媒体服务。

## 3. 产品

### 3.1 一条链接与两个空间

**作品主域邀请函（门面与推荐分享地址）**：`https://playtest.run/p/<slug>`。承载作者、作品形态、版本、这版的话、反馈与自愿关注。网页作品提供【试玩 / 体验】入口；文章在同页显示可阅读正文；视频在同页提供主动点播的播放器，不先经过一张只放【进入阅读器 / 播放器】的跳板。对外分享、广场卡片、生成卡片均优先使用此地址。

**作品独立子域（内容与运行隔离）**：`https://<slug>.playtest.run`。一个 slug 对应一个作品身份和内容源，默认指向当前版本。网页目录按原字节分发、隧道响应体不改写，不注入平台 UI 或强制门禁；保留原有从邀请函进入及直接分享子域的能力。文章和视频的正文展示、播放器与资源交付规则见 §3.16，不能借格式扩展把创作者脚本放进根域。slug 的档位与命名规则不因形态改变；同一网页作品可以在上传与隧道之间切换，不能把「可以切交付方式」解释成随意把一篇文章替换成一个游戏。

引擎导出物不用路径式（`playtest.run/u/xxx`）：引擎导出物里全是绝对路径，路径式托管一定坏，所以作品永远使用独立的二级子域根目录分发内容。

### 3.2 创作者这一侧：一个 CLI 与助手入口

只装一样东西：`playtest`。普通发布只交付链接和终端二维码，不默认下载图片，不为封面建议额外请求服务器。邀请卡仍是分发能力，但通过 `playtest card` 或发布时显式 `--card <路径>` 下载；`--card -` 保留为不下载的兼容写法。原因不是卡不重要，而是自动写入导出目录会污染下一次发布，还会让取卡的等待挡住链接。MCP 仍可返回图片内容块，但不因此写本地文件。

```
playtest ./dist                       # 上传：静态目录 → 链接 + 二维码
playtest 5173                         # 隧道：本地端口 → 链接 + 二维码
playtest ./dist --backend 3000        # 混合：目录上传，清单外的路径走隧道到后端
playtest ./dist --seats 10            # 放到广场上，找 10 位试玩者（不用再写 --public）
playtest ./dist -m "改了新手引导"       # 这一版的话：门禁页、关注通知、广场卡上都是它
playtest ./dist --summary "一句话" --cover cover.png --community https://…   # 卡片文案、封面、你的群
playtest card <slug>                  # 重新拿一张邀请卡（存成 PNG）
playtest files <slug>                 # 线上这一版到底有哪些文件：路径、大小、内容哈希
playtest whoami                       # 这个令牌是谁、几个作品、匿名身份什么时候到期
playtest unlist <slug>                # 从广场上拿下来，链接照常能开
playtest login                        # 浏览器里 GitHub 登录一次，之后不再问
playtest logout                      # 撤销本机当前令牌并清除本地凭据；不删除作品
playtest ls / rm / open / versions / rollback
playtest … --json                     # 机器可读输出、日志走 stderr、分层退出码
playtest mcp                          # 作为 MCP server 跑：Cursor / Claude Code 里一句「发给朋友玩」就出链接、二维码和邀请卡
```

**CLI 的入口按任务渐进展开**（对应 M1 / M2 / M3）：`playtest` 与 `-h` 先展示发布、打开、邀请卡、作品列表；`--help` 展示完整参数和维护命令。不新增一层 `site` / `project` 子命令，也不删除已有脚本正在使用的命令：减少首次阅读量，而不是把同样的复杂度换一个名字。只读或取卡命令不写目标时使用当前目录的发布记录；删除、下架、回滚仍要求显式目标，不猜「最近一次」。所有作品命令都接受作品标识或已发布目录。

参数错误在联网前说明：只给发布选项却没给目录不能当帮助成功退出；端口、人数必须为正。本地端口分享不能使用的发布选项直接报用法错误，不再忽略后继续发布，避免开发者误以为封面、说明或上广场已生效。`--api` 无论写在子命令前后都生效。未实现的 `--watch` 不放进可运行示例，目录变更后再次运行发布命令即可。

**参数面收敛**，理由都是「一个问题不该有两个参数」：

- **`--seek` 并进 `-m --note`。** 对开发者「这版改了什么」和「想让你看什么」是同一句话，对玩家在门禁页、在通知正文、在广场卡上看到的也是同一句话。留两个只是逼人分辨一个不存在的区别。`--seats N` 现在单独表示「正在找人测，找 N 位」。
- **`--isolated` 收成三态**（`auto` / `on` / `off`），不再有 `--no-isolated`。它本来就是三选一，两个互斥布尔还得靠 `conflicts_with` 才能表达「不能同时说」。
- **`--card <路径>`**，写 `-` 就不存；`--card-out` 与 `--no-card` 两个参数、`card --out` 与 `--card-out` 两个名字都没了。
- **`--to <slug|new>`** 取代 `--site` 与 `--new`——「发到哪个作品」是一个问题，而原来那两个能同时给。
- **`--force` 改成 `-y`**，和 `rm -y` 是同一个意思：别问我了，照做。
- **`playtest followers` 撤掉**，关注数并进 `ls`：单开一条命令只为看一个数字，不值一个命令名。
- **`--api` 提到全局**（原来在 11 处各声明一遍）。没有 `--api`、也没有 `PLAYTEST_API` 时，用 `~/.config/playtest/config.json` 里上次记下的控制面；文件里也没有，才是线上。令牌绑在那个地址上——若这时仍默认打线上，会另开一个匿名身份并把本机配置盖掉。

**`--json` 是一个渲染器，不是一套平行实现。** 每条命令产出一个结果对象，人话和 JSON 各渲染一次。之前 `ls / rm / open / card / followers` 在两个文件里各写了一遍，而 `versions / rollback / unlist` 只有人话那一半——`playtest rollback --json` 会往 stdout 写一条裸链接，破坏「stdout 只有一个 JSON 对象」的承诺，`versions --json` 则什么都不写。现在做不到「只实现一半」。

第一次运行不登录也能拿到一个 24 小时的匿名链接——免登录是 M1 的要求，也是 GitHub 登录在大陆间歇失败时的兜底（§5）：第一次必须在任何登录之前就成功。终端里直接画二维码，手机扫码就是 M1。

**发布成功时打出的东西**：作品与版本、分享链接、终端二维码、匿名到期提醒和结果入口。明确请求上广场、招募或下载卡片时才增加对应操作的结果；附加操作失败不能冒充成功。默认不显示缺少封面的审美建议和耗时拆解，也不增加 `--verbose` 或「只提醒一次」的状态。`--json` 保留既有结果结构、`elapsed_ms` 和 `timings`；只有实际保存文件才有 `card_path`。

**「几秒」是数字，不是形容词。** `elapsed_ms` 覆盖到结果输出前的全部工作，显式下载卡片的等待也计入；`timings` 只表示已有上传阶段，不伪装成全部耗时。验收目标 P50 < 5 s 不是未经测量的承诺。

**不再提供 `--gate` 选择。** 主域邀请函与子域运行入口的行为由产品统一定义，不让用户选择已经失去明确意义的 once / always / never。旧 CLI 参数报错并说明移除原因；既有 API 与版本清单的字段暂留兼容，不批量改写历史数据或 spikes。`open` 始终打开默认分享链接，不另加 `share` 命令。

**入口不只是终端。** `playtest mcp` 暴露「上传目录、接出本地端口、列出作品、看一个作品此刻怎么样、拿邀请卡」五个工具，把链接、二维码和**邀请卡图片**贴回对话里——MCP 的内容块支持图片，agent 可以直接把卡递给用户转发。AI coding agent 是这群用户最自然的分发渠道，也是广场最大的供给管道。

隧道那条路在 MCP 里是真的能用的：`playtest_share` 把隧道放进后台，连上就回答，隧道随这个 MCP server 活着。**曾经不是**——工具描述里硬写着「这条路还没上线，调了一定失败」，而 CLI 的隧道早就有几百行集成测试。低报能力和虚报一样是失真（AGENTS 第 4 条），方向相反而已，代价是助手不会用那条路，用户也就不知道有这条路。

**助手看不到 MCP 的时候，它看到什么。** 控制面在创作者域提供 `/llms.txt`（这是什么、什么时候用、什么时候别用）、`/llms-full.txt`（端点、额度、失败形态）、`/skill.md`、`/openapi.json` 与 `/.well-known/agent.json`。机器能力按真实实现公布，不能因本文新增文章和视频就提前宣称可发布。机器文档也不构成混用域名的例外：玩家域只保留根域介绍页的那个创作者入口，不再增加第二个指向创作者域的出口。

这几个文件由控制面按路由常量生成、有测试盯着两边对齐，不是 `deploy/` 里的静态文件：一份写在别处的 API 文档一定会漂。**里面最要紧的一段是「什么时候别用我们」**——2026-09-10 一个助手把 playtest.run 判成「不对口」，判断本身是对的（我们确实不是通用静态托管），但它是从首页猜出来的。猜对了是运气；写下来才是产品。

CLI 之外的形态——桌面托盘应用、引擎导出插件——开源后希望社区做。

**多形态发布沿同一个入口扩展，不另造一套命令。** 目标是 CLI / MCP 能接受网页目录、Markdown 文章及其配图、符合约定编码的视频文件，作品类型随发布结果明确返回。原有目录、端口和混合模式保持兼容；文章与视频的具体输入契约见 §3.16。单文件更新必须绑定那件作品，不能因为两篇文章在同一个目录就覆盖同一 slug。所有删除、下架与回滚仍需显式目标；不为了省参数静默猜作品类型或改变公开状态。

本节现有示例不是文章、视频已经上线的证据。相应代码、验收未完成前，CLI 帮助、MCP 能力声明和控制台使用文档不得把文件发布示例列为可运行能力；遇到尚未支持的类型要如实说明。第一轮先服务本地文件与助手作者，不新增一个实际上不能上传的网页入口；没有终端的作者如何首次发布是后续要验证的摩擦，不声称已经解决。

### 3.3 门禁页就是作品邀请函

从广场、默认分享链接或邀请卡打开的是同一张作品邀请函；网页子域直达保持直达，不在这条路径追加门禁。邀请函和卡（§3.4）使用同一个作者、标题、作品形态和版本说明，让人知道将要接触什么。文章正文和视频播放器就在这张页面中，不因复用旧的游戏版式而多加一次跳转。

它不再只是为了拦截而存在的“门禁”，而是每一个作品唯一的**统一门户（Front Door）**。

**从上到下：**

1. **封面视窗**（`--cover`；4:3 饱满入场画框，高光发丝描边；没有封面就用作品名排一张与广场共用颜色、首字花押、同心星轨坐标与印章的 Playtest Pass 几何字卡，那是设计好的版式，不是假装的截图）。中段带有物理打孔虚线撕票缝，上下比例舒展均衡。
2. **「某某 邀请你试玩 / 体验 / 阅读 / 观看《作品名》」**——根据已确认的作品形态选动词，不把所有内容叫试玩。创作者头像与昵称沿用现有规则：有 GitHub 头像用 GitHub，未配头像者按名字 / slug 生成 ODD FOLK 角色；不为了身份显示要求体验者登录。
3. 一句话介绍（`--summary`）；`v7 · 9 月 9 日 · 「改了新手引导」`（版本、日期、这版改了什么），以引言式微卡片呈现。
4. 名额那一行（设了 `--seats` 才有）：游戏找试玩者，文章找读者，视频找观众，其他作品找体验者。**加入 = 留了名字的人**，不是打开、读完或看完的人；到齐后仍可接触作品，不把招募数量做成内容门禁。
5. **作品为主，关注为独立次行动**：
   - **【开始试玩 / 体验】**：采用纯钛白高对比底面（`#ffffff` 白底墨黑字），具备确定性按压微动效与触感内阴影，作为页面第一视觉重心；配合有明确标签的「你的名字（可不填）」输入框。为什么不是暗色黑曜青绿按钮：暗色按钮与暗卡片背景（`#121215`）对比度极低，造成 Dark on Dark 视觉疲劳，容易被误认为不可点击的置灰态；纯白按钮与暗底形成 18:1 的强烈反差，行动意图清晰果断，冷萃绿仅作为准星焦点与状态小点的克制点睛（Accent by Scarcity）。点击后在新标签页（移动端直接导航）打开作品专属子域 `https://<slug>.playtest.run`。进入游戏后由游戏自身按 HTML5 标准交互处理音频播放。名字进开发者的点名册（§3.5），不进任何账号。
   - **文章与视频**：文章不要求点开始才显示正文；视频使用标准播放控制，由用户手势启动，名字可不填。封面与身份栏不能挤成一整屏广告再把作品藏在下面；不自动播放、不连播下一件作品。网页的开始按钮不复制成它们的额外入口。
   - **【关注更新】**：与分享、群和举报收在卡片底栏，铃铛配短标签，不另占一段。首次点击打开卡片外的紧凑通知对话框；邮箱输入不在卡内扩张，关闭后作品卡保持原位。原生 dialog 提供焦点与 Escape，无脚本仍可用锚点打开和关闭。
     - 若当前设备已激活（有 `pt_me`）：直接呈现**一键秒关**按钮（未关注时点击瞬间变为【✓ 已关注更新】，已关注时可取消）；
     - 若当前设备未激活（首次使用）：对话框只放标题、邮箱和提交，以及一行真实的确认信与邮箱用途说明。通知是自愿的后续动作，不增加开始体验的步骤。
6. 辅助信息：**「开发者的群」**（`--community` 设了才有）与 **「分享」**（公开作品才有）放在关注同一工具行，不各占一段；分享以可访问名称和悬停提示的图标表达，打开分享页给出卡图与链接（§3.4）。有效期紧邻版本日期，以时钟图标与短文字表达，不漂在页尾；不靠悬停才能看见到期事实。
7. **反馈与过程**：所有类型在作品页有可选的一句话反馈入口，绑定正在展示的版本；网页内的 SDK 反馈仍由作者自选。公开反馈默认关，作者选择公开后最多显示三条，署自愿留下的名字或「一位体验者」。作者主动公开的版本说明按时间展示（§3.7），正文、反馈与历史都不因类型不适配而被塞进游戏评价文案。
8. 最底下的同一操作栏里，举报靠末端、视觉最轻；免费档与匿名链接的角标「由 playtest.run 提供」，Pro 可去掉。卡外上方只保留一个带原有图形标记和染色 `run` 字标的回广场入口，不重复摆返回文案与另一个弱域名。

**它为什么在主域 `/p/<slug>`，三个理由**：帮助接收者判断内容与作者（M2b）；在一个地址看版本说明与关注更新（M3c / M3d）；让反馈指向明确版本（M3）。不同形态按实际发生的动作记事件：显示文章不是点击开始，视频页面打开不是播放。隧道那头不在线时明确说电脑暂时不在线，不假装作品仍可用。

**网页作品子域彻底纯净**：忠实分发创作者的文件或转发隧道，不拦截顶层文档、不强加门禁 Cookie（废弃 `pt_gate`）、不注入平台重定向。文章与视频的展示产物是 §3.16 明确选择的独立交付，不在原有 HTML 或视频字节里偷偷加东西。

**常驻与回访**：主域邀请函是作品的标准门户，回访时看到当前版本与作者选择公开的过程。网页保留进入作品与纯净直达，文章同页可读，视频同页可播。邀请函外壳维持轻量，不引第三方脚本，首屏出现时间是验收目标；正文、图片、视频按各自预算计量，不能沿用「整页十几 KB」去掩盖媒体实际大小。服务端直出 Open Graph 元数据。

**微信里**：主域邀请函给「在浏览器中打开」的提示，但「开始」始终在、始终可点——只给提示不给路径触及微信规范 §3.2.3。

### 3.4 邀请卡

**是什么。** 每个作品一张 PNG，由边缘按当前版本渲染，`/_playtest/card.png`（1080×1350，竖版，发群里用）与 `/_playtest/card-wide.png`（1200×630，横版，做链接预览的 `og:image`）。CLI 显式下载时才保存文件并打出路径；`--json` 提供卡片地址和可选的保存路径，MCP 直接返回图片、不自动落盘；控制台里能预览、保存；门禁页的「分享」打开一页只放这张图、「保存图片」和「复制链接」（支持 Web Share API 的浏览器直接弹系统分享）。

**上面有什么**：封面（或字卡）；「某某 邀请你试玩 / 体验 / 阅读 / 观看《作品名》」；一句话介绍；版本与日期（匿名链接则写到期时间）；名额（设了才有，称呼随形态）；二维码指向主域邀请函，带 `?from=card`；一条撕票线；角落「playtest.run」（Pro 可去掉，和角标同一条规则）。动词帮助 M2b 判断内容，不额外堆引擎名或品类徽章。

**上面没有什么，为什么**：玩过人数（0 人不说是 §3.5 的规矩，卡上没有可数的东西，就一个字不放）；「限时领取」「立即抢」任何优惠券口吻；「游戏 / 体验」品类；任何我们的营销话。**硬线：卡的口吻是「某某邀请你」，不是「你获得了」。** 理由不只是审美——微信《外部链接内容管理规范》§2.5 点名的是「以游戏、测试等方式吸引用户参与互动」的营销 H5，一张长得像兑换券的卡是在往规则最针对的形态上靠。邀请函是私人递出的东西，兑换券是商家发的东西，我们只能是前者。

**它为什么值钱**：它借的是 ZCODE 那类凭证卡的**克制**——深底、一张图、一个署名、一个日期、一条撕票线，别的没有。「值钱的感觉」来自留白和真人名字，不来自更多的字。

**「分享」按钮只在公开的作品上出现。** 私测的邀请不该被转发；公开求测的作品，玩家帮开发者招玩家正是开发者想要的——这是邀请环的病毒那一半。

**它是我们在微信里唯一被看见的面。** 开发者愿意转发一张好看的卡，角落那个名字就是获客环（Carrd 创始人说过「Made with Carrd」是它的增长来源）。

### 3.5 知道结果

不做分析平台。对一轮 5–50 人的反馈先给**计数、原话与对应版本**，不画漏斗或把小样本包装成精确结论。底层观测能力与作品形态决定可以说什么，不为了三种作品看起来一致就发明同一套「玩过」数字。

**所有作品共同的事实**：作品页或内容请求、能观察到的资源失败、自愿留名、版本绑定的反馈，以及邀请卡、通知、广场、合集等来源。去重会话不是认证真人；没有采集到的信息显示「未采集」或不展示，不写成 0。页面打开不代表接触完内容。

**网页作品**：邀请函的「开始」点击、子域 HTML 请求和 SDK 的就绪事件是三件事。边缘收到请求不证明首帧出现；首帧、实际互动、加载阶段或停留需要相应客户端信号。未接 SDK 时只给可观察到的部分，不写「已进到游戏」「玩了五分钟」。

**文章与视频**：自带阅读器 / 播放器可以报告实际展示、播放、暂停、播放错误等已实现事件，但不能把滚到底当成读懂、把拖到末尾当成完整观看。第一轮只呈现已采集事实、回访与反馈，不把完读率、完播率作为已有能力。反馈至少带作品、版本和可选正文；段落定位、视频时间点只在后续具体验收后增加，不先展示空按钮。

**加一行脚本才有的**（可选 SDK `playtest.js`）：JS 错误与堆栈；加载分阶段用时；自定义事件 `playtest.event("level_done", {level: 3})`——文档只教一种用法：标记进度里程碑；最后一个事件与最后一次输入的时间戳；右下角一个反馈按钮——玩家写一句话，附截图、设备、版本、进入多久；反馈提交后那一屏是**玩后的落点**（§4.6）：「谢谢」、「有新版本时告诉我」、「看看别的作品」。反馈不设必填项。

**创作者在控制台看到的不是仪表盘，是点名册。** 每版一段话；下面是具备相应 SDK 信号后的网页示意，不是仅凭边缘日志就能生成的报告：

```
v7 · 9 月 5 日 14:20 · 「改了新手引导」
8 个人打开，6 个人进到游戏（2 个在加载时走了——其中 1 个微信 Android，game.wasm 下到 61% 中断）
3 个人玩了 5 分钟以上，2 个人回来过第二次；来自：邀请卡 4 · 广场 2 · 微信 2
1 个 JS 错误撞了 3 次（TypeError: Cannot read 'x' of undefined @ main.js:412）
1 条反馈：「不知道要按哪个键」· 小雨 · 附截图 · iPhone 15 Safari · 进入 47 秒
12 人关注着这个作品，下一版发出去他们会收到通知
```

点开是这一版的会话列表，每人一行，有名字的显示名字，可按「停留最短」排序；反馈单独一条流。不画图表。手机上也能看。这段话在控制台里怎么摆、控制台整体长什么样，在 §3.13。

**反馈可以公开**（每个作品一个开关，默认关）：提交处事先说明是否可能展示，未经此告知的私下反馈不因作者后来打开开关就追溯公开。符合公开约定的最近三条显示在作品页，署自愿留下的名字或「一位体验者」；作者可以隐藏。它是带版本的原话，不是讨论区，没有回复、点赞或楼层，也不自动生成好评或精选结论。

**数据边界**：名字自愿，邮箱只用于本人选择的通知且作者看不到；不跨站追踪，不在作品结果中保存 IP 或精确位置。结果留存按档位（§6），不因 build in public 自动永久保留或公开。平台说明自己收集什么、怎样使用与删除；这不替作者的作品内容或自行采集的数据作合规保证。

### 3.6 关注与通知

**是什么。** 作品关注表示「有新版本时告诉我」，跨形态共用；合集与广场关注另按新作品摘要触发（§3.15），不能互相顺带订阅。渠道是实际已开放的邮箱与浏览器通知，不能把作品、合集、作者三者混成一个关注按钮。

**一键关注与账号。** 首次自愿关注可填写邮箱，邮件中先预览打码邮箱，明确确认后建立关注并登录同一个长期账号；首次作品访问不经过这些步骤。已经登录的设备在主域邀请页一次点击关注，作品运行子域不接收平台身份。换设备使用统一登录；没有可用通知渠道时，保存关系与实际送达必须分开说明。

**触发什么。** 关注的作品成功提交可访问的新版本：一封「《作品名》更新至 v8」，正文突出作者写的 `--note`，主行动随形态为试玩、体验、阅读或观看，链接带 `?from=notice`。每作品每 24 小时最多一封，合并时只指向实际可访问的版本。上传失败、回滚、修改公开设置不冒充一次新创作；撤下、到期或限制访问后不让旧队列泄露内容。

**创作者看到的是数字，不是邮箱名单。** 控制台和 `playtest ls` 给关注数；邮箱由平台保管、通知由平台代发。删除作品停止相应通知并清理关注关系，不把读者和观众地址变成作者可导出的营销名单。

**退订**：每封信底部一键退订链接（一个令牌，点了就退，不问为什么）；关注页里逐个取消。退订立即生效。

**边界**：作品看迭代，合集看新投稿，广场看周报；每一种都明确征得选择。不做关注人的粉丝系统，不要求订阅才能打开作品，也不假定所有读者都想关注同一作者的所有创作。

### 3.7 版本

**一个作品，一个持续的身份。** 每次成功提交形成不可变版本（`v1, v2, …`），不是上传了几个分段就算一版；slug 指向当前版本，回滚只改指针。文章改稿、视频修订与网页更新都沿用这个身份，会话、反馈、说明与通知绑定具体版本，不能发布下一版后把旧反馈重新挂到新内容上。

**版本说明是 build in public 的最小表达。** 作者可写这版尝试什么、改了什么、想听什么，不设必填模板、不自动生成进展。当前说明在作品页和更新通知里复用，不要求再写一条动态。未填就不编造，回滚也不伪装成「新版本发布」。

**过程在现有作品页里，不再建一个进度平台。** 作者可主动选择公开已发布版本的日期、说明和版本号；后来的人在同一作品页按时间看变化（M3d）。当前内容默认仍是当前版，公开说明不意味着旧文件、私下反馈、源稿或编辑草稿一起开放；不追溯公开作者未选择的记录。首批不承诺可运行的历史版本地址、自动版本差异或「这条反馈导致了这次修改」。

**留存、撤回与权限优先于过程展示。** 文件与结果按档位保留，旧文件已回收就说明该版本内容不可打开，不用当前内容冒充旧版。取消公开说明、作品转私密、删除或到期时，相应公开快照、搜索与缓存必须失效；过程页不能成为绕过访问权限的后门。存储去重只改变存几份字节，不改变作品的权限。

**不是所有创作关系都叫版本。** 同一篇文章的改稿是版本；给一个工具写的长篇制作过程、为它拍的独立视频是另外的作品，可用已有合集放在一起（§3.15）。不把它们轮流覆盖同一 slug，也不因此新增「项目」对象。隧道仍只有在线状态和会话，不是可重现的版本，不触发版本通知；需要留下过程时先发布一个静态版本。

### 3.8 谁能接触作品

三档：任何拿到链接的人（默认）；要口令；只允许邀请名单（一次性令牌或邀请码）。体验者不需要注册，既有受控访问能力仍受档位约束，所有形态的正文、媒体、配图与衍生展示都服从同一权限。网页与跨源隔离、文章与媒体 Range 请求分别验收，不只保护一张封面页。

**能打开与能被发现是两回事。** 默认链接不进广场，但持有链接的人可以转发，不称为私密。上广场、加入公开合集必须由作者明确选择，受限作品不能公开收录。build in public 是支持的方式，不是强迫所有作者公开的政策；撤出发现不等于删除作品，真正限制访问要改权限，界面要说清区别。

### 3.9 广场：目的地

**默认头像的发布门槛**：首发收敛在十种原创形象，不再靠增加素材数代替质量。生成器的抽样、配色和画稿按版本冻结，修复 SVG 封装不应让作者换脸。产品署名中的头像是名字旁的装饰，读屏只读作者，不插入物种、配色等无助于判断身份的词；独立 SVG 仍保留图像说明。一个作品在同一作品墙只出现一次，SVG 的局部引用按公开 slug 与显示尺寸隔离，同名作者的不同作品不得共享 DOM ID；不用全局随机数换取隔离，以保留可重现性。仓库内素材必须通过严格结构校验，固定种子回归必须包含真实 SVG 解析与小尺寸光栅化，不把字符串存在检查当作画面验收。发布前同时验收广场和邀请页的实际 24／32px 样式、GitHub 头像优先级、无脚本路径与窄屏布局；本机浏览器、手机真机和线上结果分开记录，不用概念页或单元测试替代未完成的发布门槛。

**是什么。** `playtest.run/`——根域那一页。对体验者是可以直接试玩、体验、阅读、观看新作品的地方；对作者是找到合适反馈与回访者的机会。它是**创作与反馈的俱乐部**，不是只追求播放量和停留时长的消费者大厅。既有游戏供给保留，文章、视频不被降格为附件。

**为什么是这个形态。** 三个可选形态：*itch 式的发现大厅*（默认公开、按热度排、点赞评论，观众是陌生大众，审核、排序公平、反作弊全落到两个人头上，把境外不备案的内容域推到监管正面）；*只放不排的告示板*（上一版的选择：不排名次、不点赞、玩家没有任何持续的东西——它把「被看到」做到了，把「回来」切断了，每个从微信进来的玩家都是死胡同）；**俱乐部**（选这个）：公开可翻、只放开发者主动公开的、免费流按时间排；但玩家可以关注、可以留名、可以收到周报；推广位透明限位。它拿到了「被看到」和「回来」，代价是内容审核和一个小型通知系统，两个人做得到。

**在哪。** 广场在根域 `playtest.run/`，管理在同域 `/console/`。它们共享产品导航与账号，不按玩家／创作者划成两个站；作品运行源仍独立（§4.1）。

**形态能识别，受众不强行合并。** 卡片动词按试玩、体验、阅读、观看区分，沿已有搜索与筛选提供网页 / 文章 / 视频的选择（M2b / M3b），不另建三个频道和三套关注。默认保留按时间发现，热门排序只用可比较的实际事件，不拿视频时长压过短文章。以下展示卡的「不放播放键」指不把全平台做成视频墙，不禁止视频作品页的标准播放控制；视觉细节中的游戏文案示例按本条和 §3.16 适配。

**页面架构：224px 侧栏与可读的作品墙。** 桌面侧栏提供品牌、文字导航与发布入口，手机收为两行顶栏。卡片以约 260–310px 的常用宽度自适应，1280px 视口通常三列，宽屏再增加列数；窄手机单列，中等宽度两列。单件作品也占一个正常列宽，不随作品数放大。封面采用 16:10，标题与简介各允许两行，简介 14px、辅助信息至少 12px；作者与事实在底部对齐。以读清作品与作者想听什么来决定密度，不靠强制四列或截成一行让墙看起来紧凑，让 M2b / M3b 更可信。标题栏右侧放约 300px 的搜索框（前置搜索图标、支持 `/` 键全局快捷聚焦、支持一键清空），手机另起一行；不做通栏大搜索，不在页首常驻口号。单行工具栏左侧通过黑曜微浮雕分段胶囊在「作品 / 合集」间切换，右侧排序用「最新」「热度」（按近 7 天去重会话排序，合集页隐去排序）；最新按更新时间排列，明确标识的推广保留在前，求反馈不再覆盖时间顺序。统计口径收进旁边可点击、可键盘展开的说明，保持事实可查，不让后台统计解释占住作品区。彻底避免垂直双层下划线 Tab 堆叠。

**发布说明是一张清晰的命令便条。** 入口用黑曜钛金主按钮；原生对话框桌面约 672px 宽、外留白约 20px，只留短标题、一个集成模式切换与复制的命令区、当前方式必要的运行提示，以及安装与控制台 / 文档链接。命令组件用深邃黑曜钛金底、冷白字与少量翠绿终端高亮，让最需要读取复制的内容成为视觉中心；桌面常用命令单行，窄屏仅代码局部横向滚动，不把命令任意折断。导出目录、本地端口、带后端共用一个命令区，不把复制、帮助和营销说明拆成多块卡片。参数按需展开，用参数与含义对齐的两列排版；不再用多段解释挤占首屏。脚本失效时可用锚点打开关闭、切换模式与手动选择命令；增强脚本提供复制反馈、焦点管理和 Escape 关闭。不增加发布向导或玩家登录步骤。

**常驻导航。** 广场、关注、我的作品、我的合集分别对应发现、回访、创作管理和组织。广场内部以单行工具栏的分段胶囊「作品／合集」切换，默认作品；作品与合集不混排成一个列表，挑战仍是合集的一种。管理入口与公开索引明确区分，不用一个含混的「合集」同时代表两种任务。

**为什么参考稿上的包装都拿掉。** 上一版有六个筛选、两种排序、三个分段标题、每张卡上三个按钮——它们把一面「有什么可以玩」的墙排成了一张后台列表。只提供 §3.15 中缩短发现路径的控件，不恢复六重筛选与每卡多按钮。卡不跟那张大表面卡走。口号、门口、播放键、面包屑、「无需登录 / 不用安装」和墙底那句规则，都不让任何一张卡更近。字标旁的播放键看起来像会动，点了只回首页。发布只留命令便条。说明以 `:target` 保留无脚本入口；有脚本时增强为有焦点管理、Escape 关闭和关闭后焦点归还的对话框。三条命令用单选标签切换。说明里那条控制台链接，是玩家路径上唯一去平台根域的出口（AGENTS 第 7 条）。

**默认头像的艺术约束**：ODD FOLK 用原创轮廓、明确表情、协调色组与分层服饰，让 §1.2 M2b 中玩家判断「谁邀请我」更快、更可信；借鉴收藏级 PFP 的角色辨识度，而不是复制无聊猿的具体角色、商标或素材。角色先于换装：保留原有六种角色，增加蘑菇居民、玻璃幽灵、陶土精灵、毛团野兽四种原生形象。它们各自拥有独立身体剪影、五官位置与画稿：菌盖与短茎、半透明漂浮体、缺口釉面陶偶、无脖子毛绒身体，而不是共用动物胸像换外壳。每种都要在没有帽子和服饰时成立；24px／32px 仍能分辨大轮廓。四种原生角色不套用旧头饰、服装、配饰或眼镜，只有适配的三种眼神与四种表情；不绘制的维度固定为 0，签名不拿不可见的随机数冒充多样性。预览和导出明确标注原生身体、不适用换装，但不为玩家新增选择步骤。SVG 使用本地矢量色块、线条和轻量渐变表现材质，不用滤镜堆出渲染成本。背景退后、脸部优先；广场用 24px、邀请页用 32px 的圆形头像，不沿用看不清五官的 16px；不放签名、版号等不可读装饰，大图增加克制的轮廓光、缝线和高光。素材使用仓库内原创 SVG，不增加玩家请求、登录或依赖。生产 Rust 与本地概念页共用新增矢量素材，种子统一按 UTF-8 采样；版本固定时确定性重现，不承诺种子绝不撞脸。具名作者按公开显示名稳定生成；空名字或「匿名开发者」按作品 slug 生成，而不是把占位文案当身份让所有匿名作品长同一张脸。两处共用同一取种规则，不增加匿名身份字段；现有数据没有公开作者 ID，因此不承诺匿名跨作品同脸或同名作者必定不同脸。修改抽样权重或画稿升级生成器版本，明确旧版本种子会换脸，不把组合数宣传为实际独立作品数；本地概念页不是玩家侧新增编辑器。

**卡片上有什么，只有这几样**：一张贴在主舞台上的物件卡。上面一块横的插画窗（16:10），有 `--cover` 就是封面图，没有就是既有按 slug 定色、带首字花押的字卡；不因文章、视频没有截图而编造封面。窗的左上角最多一个标——「推广」或「正在找反馈」。右下角按形态用「试玩 / 体验 / 阅读 / 观看」，悬停才出来，触屏上一直在；整张卡仍是指向主域邀请函的一个链接。窗下作品名只出现一次；求反馈时写「想听什么」与作者原话，其余用简介。最底左边沿用创作者头像与名字，右边只放一件事实：有招募名额时「6 / 10 位」；匿名作品「还剩 5 小时」；有可比较的近七天打开会话数据时「12 次访问」；现有网页开始事件只能写「12 次开始」，并在提示中说明为近七天点击开始的去重会话；没有对应事件时只写最近发布时间。访问按 §3.15 的口径，不能拿既有开始计数直接改名，不能称为玩过、读完或看完的人数。卡上仍没有引擎名、关注、举报、第二个可点控件、点赞、评论或名次；关注与举报留在作品页，不为多形态把作品墙改成播放器墙。

**长相与色彩。** 界面底色 `#09090b`（黑曜基底）、侧栏 `#0c0c0e`、卡面 `#121215`、浮层面板 `#18181c`，文字 `#f4f4f5`（zinc-100）；以黑曜钛金层级与细边线分层。品牌字标使用仓库原创 SVG 轮廓，统一小写几何字形、字距、笔画与基线，`playtest` 与 `.run` 等高等重；全站与邀请函使用同一素材，不依赖系统字体或远程字体加载。冷绿高光偏青（`#75cdb5`），在中性近黑表面上以窄棱边和小范围青绿反射表现材质，不铺亮绿雾光或密集点阵。主动作（发布作品、开始试玩、控制台主操作）采用黑曜钛合金材质：纵向暗黑金属渐变、顶部冷萃绿晶体棱边（主动作局部高光 `#71e8bf`）与内部微量弥散光；侧栏发布按钮可有静态绿核状态点与 `CLI` 单行胶囊标牌，不用常驻呼吸动画。主题高光与字标 `.run` 采用冷萃绿（`#75cdb5`），状态辅以通透冷萃微标；文本选区为冷萃绿（`#57ad9540`）。字卡占位图采用近黑绿灰基底与边角一层低饱和反射，首字花押采用超细等宽冷白微光文字，右上角保留 slug 单色微水印，左下角配毛玻璃终端标签。发布命令舱采用深邃黑曜钛金底（`#101014`）与翠绿终端语法高亮。卡片是有边界的完整物件：封面铺满上半部，悬停时边框呈现微弱冷萃绿辉光（`border-color: rgba(87, 173, 149, 0.4)`），标题、两行说明与底部事实可读。悬停轻抬并微放大封面，键盘焦点清晰，触屏不依赖悬停发现动作。作品墙由服务端直出；本站小型增强脚本负责对话框、复制反馈与图片失败回退，脚本不可用时基础浏览和命令选择仍可用。为什么不是长春花紫或大面积纯色色块：深色背景下大面积实心纯色会抢夺作品封面的注意力；黑曜钛金与克制的局部微光能建立可信的动作层级，同时把视觉舞台留给作品本身。

**交互的几条硬线。** 能点的东西键盘都能到，落到哪儿哪儿有一圈纯钛白冷光环（`:focus-visible`），鼠标点不出这一圈。触屏上控件的点击区域不小于 44px。悬停才出现的东西（动词）在触屏上一直在。一切过渡在 `prefers-reduced-motion` 下关掉。发布说明在桌面居中、在手机从底部升起，点遮罩或右上角的 × 都能关；增强脚本可用时以原生 dialog 打开，Esc 关闭、焦点返回触发入口；无脚本时仍能用锚点打开与关闭。链接不带下划线。

**为什么保留紧凑的完整卡面。** 完全无框的缩略图墙缺少可点击物件的边界；多层内框又缩小作品本身。现在保留一圈细边和内容底板，让封面直接贴合卡片上缘：既能辨认点击范围，又让作品占据视觉中心。卡上不堆多个操作按钮，整张卡只去邀请函；邀请函延续同一封面，以同源原生视图过渡连接卡片与开始区。不支持该能力时正常导航，减少动态效果偏好下关闭过渡，不用等待动画的脚本阻塞打开。

**谁能上。** 只有开发者主动公开的作品，默认不公开。匿名 24 小时作品可以上（到期自动下来）；登录用户的作品长期在。私密（口令 / 名单）的作品不能公开。

**举报与撤下。** 举报入口在每个作品自己的页面上（§3.3 第 8 条），广场卡片不再重复放一次。同一作品 24 小时内被 3 个不同会话举报，自动从广场撤下（作品链接照常能开），人工复核后恢复或删除。推广中的作品在上推广位之前**先人工看一眼**——我们收了钱，就要看过。

**微信是分发渠道，不是浏览渠道。** 卡片和群在微信里传播；广场在系统浏览器、Discord、Telegram、即刻里被打开。在微信里翻广场永远不可靠，我们不为它优化（§5）。

### 3.10 关注

`playtest.run/me` 是回来继续的入口，与广场、我的作品、我的合集共用导航和账号。这里列出自愿关注的作品与合集，名称可打开、取消动作有明确对象；周报只在通知设置里出现，不冒充一件作品。

**未登录。** 显示「登录后查看关注」和统一登录入口；邮箱与 GitHub 都可登录同一个账号。首次邮箱验证建立最小账号，既有邮箱恢复账号，不另建玩家身份。关闭弹窗返回原页；公开内容仍可继续浏览。

**已登录。** 显示关注列表与通知设置。没有邮箱的 GitHub 账号也有同一份关注关系；尚无可送达渠道时说明已保存关注，并提供账号中的邮箱关联入口，不承诺已能收到邮件。作品更新、合集新增内容、广场周报分别征得同意；浏览器通知只是送达渠道，不是另一种登录。退出账号不退订，退订也不撤销登录。

**名字、权限、隐私互不代替。** 账号页可设置作品署名、关联邮箱或 GitHub、退出此设备；开发者设置中主动创建和撤销 CLI／助手令牌。关联要验证双方控制权，不因同名或相同邮箱文本静默合并其他账号。邮箱只给账号本人和平台，创作者看不到关注者邮箱；原有匿名反馈不追溯署名。

**失败不伪装。** 登录链接单次有效、一小时过期，GET 只预览，明确确认后登录；网络失败可以重试，已消费或过期重新发起。发送成功只代表进入队列，不冒充收件箱送达。本机 log 只写日志，线上实际启用的邮件服务另有投递记录。Cookie 失效显示重登，服务不可达显示加载失败，不宣称没有关注。

### 3.11 推广位

**是什么。** 开发者为一个作品买一个时间窗，窗内它出现在广场顶部的推广位上，**永远标「推广」**，每屏最多两张，超出排队（按购买顺序、按日历顺延，控制台里看得到排到哪天）。两个 SKU：**推广 3 天**、**推广 7 天**；一个附加项：**进本周周报**（周报里单列一段「推广」，最多两个）。

**规则**：免费时间流保留，推广不购买自然排序；标签始终可见；匿名作品不能购买，上推广位前人工查看，拒绝则退款。推广不改变访问、反馈或回访的统计口径，带来的实际打开仍注明来源，不用曝光冒充实际体验、读完或看完，也不保证人数或好评。

**为什么现在就设计、什么时候开卖**：形态现在就定，因为它决定广场页面的版式和数据结构；开卖要等境外主体与支付通道（Stripe，含支付宝）落地（§9）。在那之前控制台里「推广」一节如实写「尚未开放，主体落地后开通」，不放一个不能点的按钮；运营者可以通过管理接口**赠送**推广（冷启动期给好作品送几天推广，标签仍是「推广」）。

**为什么不是「付费排名」**：排名把首屏交给最有钱的，推广位只是多出来的两个格子。为什么不是「付费去广告」：广场上没有广告可去。为什么不卖「更多流量」：流量是成本边界不是购买动机（§6）。

### 3.12 明确不做

分两栏。左栏是**物理**：成本结构或安全边界决定的，不随产品方向变；右栏是**现在不做**：形态原因，方向变了可以再议，要先改本文。

**物理，不放：**
- 服务端运行用户代码——只分发静态文件、转发连接，文章展示仅经过平台明确维护的受限渲染路径，不执行作者脚本、构建命令或插件。接受视频文件不等于接受任意转码任务。
- 没有硬上限的免费——月配额加每 slug 每小时熔断（§4.8、§6），SIMMER 的死因。
- 首次试玩、体验、阅读或观看要登录或安装；不因新形态增加必经跳转。
- 偷偷改写原件或注入原有网页——网页目录与隧道响应体保持原字节，SDK 由作者自选；文章阅读器与视频播放器是单独声明的展示方式，源稿与视频原件不改写，衍生产物另存。这是一条能按原件哈希验收的边界。
- 替体验者录制屏幕或行为回放。作者主动上传的原创视频是作品，不属于这条「不录像」；两者在界面、隐私说明与实现上不能混淆。
- 原生包分发、游戏引擎、编辑器、云端构建。
- 通用分析平台：热图、漏斗、分群、A/B、DAU / MAU / 留存曲线、AI 总结。
- 大陆境内服务器与备案（§5）。
- 地图与任何基于位置的东西。

**现在不做，理由在形态：**
- 无限文件托管、任意格式预览、直播、任意编码转码、多码率视频平台——先让 §3.16 的有限格式完成发布与反馈，不把 S3 接入误当成这些能力已具备。
- 在线写作 / 剪辑工具、CMS、个人动态、日更打卡、粉丝榜、跨平台自动发帖——作者在已有工具创作，短过程用版本说明、长过程用独立作品与合集。build in public 不以经营人设或迁移全部工作流为前提。
- 聊天室、私信、评论区式的开放讨论——五个人、24 小时到期的链接上房间永远是空的，空房间比没有房间更伤开发者；聊天正是「挺好玩，有个 bug」这种零信息反馈的温床。公开反馈（§3.5）是开发者可控的单向展示，不是讨论区。
- 算法推荐流——排序只有三种：时间、7 天人数、透明的推广位。
- 给玩家卖东西、给开发者变现——我们卖的是被看见，不卖游戏；不碰支付商对内容的压力。
- 按名次排的榜单、「官方精选」——两个人没有编辑精力；将来若做，标签叫「我们在玩」并写明是人挑的。
- 孵化、评审、基金、付费招募测试者的双边市场——广场让玩家自己留下来，不卖测试者、不承诺人数。
- 关注开发者（而不是作品）、完整开发者主页——个人作品集由普通合集承接；关注按作品、合集与广场三级。
- 玩家 App、微信小程序壳。
- 帐号托管、代跑。

### 3.13 控制台：创作者的工作台

**多种作品共用工作台，不复制后台。** 作品墙、版本、反馈、邀请卡、设置的组织保持不变；标题、开始动作与事实计数随作品形态适配。文章没有「进到游戏」，视频没有伪造的「读完」，未采集不显示为零。公开版本说明的选择与撤回放在已有版本 / 设置语境里，不新增 build in public 仪表盘；以下排版里的游戏计数只是网页作品有相应信号时的示例。

**使用文档。** 主域工作区提供免登录的 `#/docs/<章节>` 阅读入口，覆盖快速开始、发布与更新、分享与招募、管理作品、脚本与助手、常见问题六章。它是全局帮助，不占作品分页签。控制台的发布弹窗、发布空态、作品页与令牌登录的帮助链接到相应章节：让 M1 首次发布、M2 分享和 M3 回看结果更短，而不是新增一个上传流程。普通发布示例不默认上广场、不承诺自动下载邀请卡；更新示例带作品标识时明确目录仍需替换。

文档使用现有 Preact 与控制台样式，无 CMS、外部字体、搜索服务或新依赖。正文限制行宽、舒适行距，章节用留白和细线区分，不堆满装饰卡片。桌面固定章节目录，手机提供可展开目录；代码块独立横向滚动、可复制且有失败提示；保留键盘焦点、直接地址、刷新定位和减少动效支持。安装入口指向现有 Releases，由用户选择适配系统的文件，不假装识别设备或安装成功。产品决定在 DESIGN，命令真实契约在 CLI，文档围绕任务组织，并做关键用法一致性检查。

**资源预算。** 邀请函基础样式不超过 6.5KB，广场与关注页的共享工作区样式不超过 23KB（均为未压缩硬上限）；增量只用于可访问的发布弹窗、44px 触控区、减少动效、响应式侧栏和关注列表，优先共用源码而非另加组件依赖。为什么不是继续守原来的 6KB / 20KB：当前黑曜主题与发布命令舱仍没有增加请求和依赖，实增约 2.2KB；删掉键盘、触控或动效降级来满足整数预算会让 M2b 更不可信。上限不是增长目标，越界仍须先回到本文说明取舍。玩家页不加载外部字体与第三方脚本。

**登录由外壳统一处理。** 点击未登录的管理入口或账号，原地打开邮箱／GitHub 登录弹窗；关闭后焦点返回原触发项。直接访问管理地址先给明确登录空态，文档与发布用法始终开放。邮箱放在主要入口，GitHub 为同级可选验证方式；不要求访问令牌，不另设创作者注册或角色切换。成功后回到原作品、合集投稿或命令行授权意图。账号页把署名、已关联登录方式、退出与开发者凭据各自放在相应层级，不让普通人先理解令牌。

品牌区只保留准星与字标，去掉「控制台」副标题。发布用法弹窗标题前复用同一份准星图形，去掉「CLI 模式」标签；命令块与下载入口已说明发布方式，不再重复标注或在弹窗底部重复广场入口。这些删减让 M1 的下一步与 M3 的返回路径更清楚，不新增页面、依赖或玩家门槛。

**完整界面的编排。** 玩家页与控制台共用一份基础样式，而不是各自复制一套近似颜色。桌面侧栏固定 224px：品牌、主导航、作品清单、底部发布与身份；激活项用窄边标记和浅面，不让每一项都发光。发布是有文字的高对比按钮，控制台不再常驻一大段终端说明；点开才给三种方式、可复制命令、当前方式必要的一行提示；安装和后续管理通过帮助链接按需查看。原生对话框负责 Esc、焦点约束和回到触发按钮；玩家页保留无脚本的锚点降级。为什么不是新建上传页：发布仍发生在终端，不制造一个实际上不能上传的网页流程。

作品卡片用「封面—标题与说明—人物／状态」三段节奏；封面沿用作品的颜色和首字花押，边缘的邀请函也用同一个封面，不在打开后突然换成另一张星轨图。打开邀请函仍是可分享、可后退的独立地址，原生跨文档过渡只做同源增强，不用 iframe、假弹窗或请求拦截来藏导航；不具备能力时普通打开。邀请函为一张紧凑竖卡：邀请人先于标题，版本与到期事实归入同一元信息区，名字明确可不填，开始按钮是唯一主行动。关注与分享收进主行动下的一行轻量工具区；分享用有可访问名称的图标，关注保留短标签，展开邮箱时才占下一行。邮箱只在自愿展开关注之后出现，解释只在首次验证与更新时发信，绝不挡试玩。

关注页主体列关注作品，取消为弱化且有明确对象的动作；未激活设备使用统一的邮箱登录空态，周报与可用通知渠道集中在右上角「通知设置」内。广场通过左侧导航进入，空态不重复放出口。手机把侧栏收成双层顶栏，主导航与发布各有触控空间；布局不依靠压小字号、截断操作文字来塞满一行。这些调整分别缩短 §1.2 的发布、分享、回看以及 §1.3 的试玩与回访，不增加产品名词、账户步骤或数据接口。

**质感来自连续性，不来自装饰。** 控制台与玩家页共用冷灰底、钛白文字、发丝边界和克制的抬升；状态色只表达事实。作品墙打开作品时，封面连续收进身份栏，侧栏不动；返回作品墙保留滚动位置。先使用作品清单中已有的身份信息，结果独立加载，不为了动画等待网络，也不让整页先消失再出现。分页只切换内容，保持身份与导航稳定。这让 §1.2 中「回来知道玩成什么样」更短；不增加仪表盘、弹窗预览或新的后端接口。

按钮与焦点反馈约 160ms；作品封面可在作品墙与身份栏之间连续移动。页面根层保持不透明，玩家页不使用整页淡入淡出；控制台同一作品的分页立即切换，不叠加路由和内容入场动画。浏览过的数据分页在当前作品内保留，回切不重复清空取数；首次加载仍显示明确的加载状态，版本变化按版本重新取数，设置页继续按需装载。快速连续切换以最后一个地址为准。系统要求减少动态效果或浏览器没有转场能力时立即导航，完整保留链接、键盘和前进后退。玩家页不为动效增加脚本或游玩步骤。加载用带文字的骨架保留空间；刷新失败明确提示，不把取数失败说成「没人来过」。触屏目标至少 44px，悬停提示在键盘聚焦和触屏上同样可见。

**是什么。** `playtest.run/console/`，开发者登录之后看自己作品的地方。它不是仪表盘（§3.5 的规矩不变：没有图表、没有比例、没有漏斗），也不是一份报告——它是一张**工作台**：作品在上面、此刻的状态在上面、要做的几件事在手边。

**它只在四个时刻被打开**，每一个对应 §1.2 的一格，第一眼要给的东西由时刻决定：

| 时刻 | 开发者想要 | 第一眼 |
| --- | --- | --- |
| 刚发出去（CLI 打出 `console_url`） | 链接对不对、玩家看到什么、把卡拿去发 | 邀请卡、玩家链接与二维码、「在广场上 · 正在找人测」、匿名链接的到期 |
| 测试进行中（M3） | 谁在玩、出了什么事 | 「现在」那一条：近一小时几个人、最新一条反馈、有没有错误 |
| 发下一版前（M3c） | 上一版告诉了我什么 | 每版一块，数字先、句子后、来源在末 |
| 发了下一版后 | 关注的人回来了没 | 来源里的「通知 N」、关注数、和上一版比的那一行 |

外加一格**收拾**：回滚、从广场撤下、删除作品、看每版体积。

**页面是两块：左边统一导航，右边当前任务。** 广场、关注与管理共享 224px 侧栏和相同入口顺序；不再把每件作品展开成长期占位的导航树。管理作品和管理合集分开，公开作品与合集则收拢在广场页签中。窄屏仍保持这些入口可见可操作，不用角色切换藏住它们。

**首页是作品墙。** 一张卡一个作品，封面、作品名、slug 与右下一件事实沿用广场规则（§3.9）：名额、匿名到期、真实近七天访问或最新发布时间，不把所有类型叫「玩过」。只有一个作品也保留作品墙，不自动跳转；稳定的导航、发布入口和作品身份比省一次点击更重要。没有作品时给当前真正可用的发布方式与发布后会出现的内容，不把尚未实现的文件入口做成可点击空壳。

**作品页从上到下：**

1. **身份栏**：封面（或色田）、作品名、slug；玩家链接、「复制」、二维码；状态签一行：`v7 · 当前`、`在广场上 · 正在找人测`、`12 人关注`、`6 / 10 位`、匿名的到期。签是事实，不是按钮。
2. **「现在」**：一行字，说此刻——「近一小时 3 个人打开 · 最新一条反馈 12 分钟前：『不知道要按哪个键』 · 这一版 3 个错误」。没有近况就说「最近一次打开是 9 月 5 日」。这一行让控制台有当下，是它和一份报告的区别。
3. **分页签**：**结果**（默认）、**点名册**、**反馈**、**邀请卡**、**设置**。签是地址的一部分，刷新不丢。

**结果**：每版一块，块里先是四个大数字（打开 / 进到游戏 / 5 分钟以上 / 反馈；0 的不排大，退成灰字），然后是 §3.5 那段话（一句一行，0 的句子不说），然后「来自 邀请卡 4 · 广场 2 · 微信 2」，最后和上一版比的那一行（「比 v6：打开 +3，反馈 1 → 2」）。块尾两件事：「点名册」、「设为当前」（不是当前版才有）。**数字排大不是图表**——它是把句子里最要紧的两个数从行文里提出来，仍然是计数，不是比例。

**点名册**：一版一张，每人一行，停留最短在前；名字是这一行的主角，没留名字的用会话号头几位；标签说进到哪、玩到哪、来自哪、是不是回头的；展开是这个人的事件与错误。这一页不变（§3.5），只是搬进了分页签。

**反馈**：一句话是主体，署留下的名字或「一位试玩者」，版本、设备、进入多久；每条可标看过 / 处理完；开了公开反馈的作品每条可隐藏 / 恢复。

**邀请卡**：竖版和横版两张放大到能看清字；「保存图片」、「复制链接」、支持时「分享」；一句话说它去哪用（群里发竖版，链接预览用横版）。它是发出去之前最后一眼，所以单独一页，不塞进设置里。

**设置**：广场（放不放、找不找人、想让人看什么）、名额、开发者的群、公开反馈（即 §3.5 的「让玩家看到彼此的反馈」，界面上只叫公开反馈）、推广（主体落地前如实写「尚未开放」，一个按钮都没有）、版本清单（每版文件数与体积，回滚在这里）、最底下**危险区**：从广场撤下、删除作品（删除要再敲一次 slug）。

**长相。** 和玩家域（§3.9「长相」）同一套记号：墙、栏、卡三级面，共用背景（`#09090b`）、侧栏（`#0c0c0e`）、卡面（`#121215`）、品牌主色和文字颜色，以发丝线和克制高光分层；黑曜钛金与冷萃极光绿强调主动作与当前项，警示用橙色。数字用等宽字。手机优先，桌面两栏。结果页那四个数不装在四个小盒子里，用发丝线隔开排成一行——盒子把计数排成了仪表盘。作品的窗拿不到封面图就退成字卡，破图标不是一种状态。主要动作按钮采用黑曜钛金晶体棱边微光质感，次要动作用描边或文字；不让所有状态同时发光。

**文案（全站通用）。** 界面上的字只说事实，不解释为什么、不预告接下来会怎样、不安慰。一句能说完的不写两句；括号里的补充、破折号后的转折、引号包起来的自造词，都是在页面上替自己辩解，删掉。数字用「8 人打开」不用「8 个人打开了」；比较用「打开 +3，反馈 1 → 2」不用「多了 3 个人打开，反馈从 1 条升到 2 条」。按钮是一个动词或一个名词：「保存」「撤下」「点名册」，不是「让玩家看这一版」这种带宾语从句的句子——除非短了会有歧义。理由写在代码注释和本文里，不写在玩家和开发者眼前。**为什么。** 解释多的界面读起来像在道歉；一个只报事实的界面，读者才会信它报的事实。**开发者永远看不到玩家的邮箱**（§3.6），关注只有数字。

**为什么不是另一个。** *单栏、每页一列卡、卡里是段落*（上一版）——它把「每版一段话」做成了「每页一段段的话」，设置块压在结果上面，没有此刻、没有导航语境，看起来是一份文档；「点名册」是结果层的形态，不是整个控制台的形态。*仪表盘*——图表、KPI 卡、时间范围选择器，对 5–50 个人的数据是噪音（§3.5、§3.12）。*和广场不同的一套皮*（上一版的米白与琥珀）——开发者是这个产品里唯一同时进两间房的人，两套皮让他觉得是两个产品。*管理页放进控制台*——运营者用 `scripts/admin.sh`，管理页后置（§4.5）。

**现在做不到、如实写的**：隧道在线 / 离线只有边缘知道，控制面还没有这个字段，身份栏上暂不显示；「近一小时」从这一版的会话里在浏览器侧数，控制面加上专门的字段之前只对最新一版算。

### 3.14 全站一致的交互质量

**视觉以作品为主。** 全站共用 §3.9 的黑曜底色、黑曜钛金微光主动作与冷萃极光绿高光，命令区采用深邃钛金终端；作品自身的封面保留颜色。常读文字不小于 14px，辅助元信息不小于 12px；输入框在手机上用 16px，避免输入时自动放大。控制台结果与设置限制阅读宽度，作品墙按视口展开。圆角只分控件、面板、作品卡三档；阴影用于分层，动效用于反馈，不做常驻呼吸灯。为什么：M2b 要让人相信链接，M3 要让人读清事实；装饰不能挤占作品和结果。

**尺寸与材质的落实。** 主导航和常用按钮用 14px 文字、至少 44px 操作区；紧凑辅助按钮在桌面可用 36px 高，触屏恢复 44px，不靠缩字容纳操作。作品标题约 16px，页面标题 24–28px，弹窗标题 18px；发布命令 15px，运行提示 14px，版本、作者与标签至少 12px。发布说明保持 672px 上限、桌面 20–24px 与手机 18px 内边距，让命令比终端装饰更醒目。控制台作品身份、结果与设置的正文上限为 960px，避免宽屏把相关事实拉散；作品墙继续自适应。黑曜底、冷萃绿和封面构图保持稳定；侧栏发布入口保留 44px 点击区，内部可见表面收为 38px 高，避免触控尺寸直接变成厚重色块；普通卡片只在悬停时轻抬，不叠外发光。导航、整卡和按钮不带正文式下划线，正文中的链接仍可辨认。这样逐项修复 M2b 的可读性与 M3 的信息层次，避免每次打磨都换一套比例。 控件、内面板、外卡的圆角分别约 7px、10px、12px；边线保持 1px，靠降低亮度和减少重复框线减轻重量，不用半像素线制造模糊。当前导航用浅面和窄标记，不再叠一圈边框；控制台作品身份栏用底部分隔线，减少封面外再套整张卡的重复边界。邀请卡约 400px 宽、标题 22px；字卡与封面画框采用 4:3 比例，配合撕票虚线与边缘半圆打孔缺口，形成沉稳完整的入场券（Pass）物理隐喻，头尾重心均衡；主动作按钮采用纯钛白高对比底面与墨黑字，按压微下沉，成为页面第一确定性视觉焦点，冷萃绿保持为点睛色；可选姓名与开始按钮上下排列，使主动作不被输入框挤成一小块。常读文字维持既有下限，通过字重、间距与容器减重获得轻巧感。

**每个动作有明确收尾。** 请求中显示实际动作并阻止重复提交；成功在原位置简短确认，错误靠近触发它的动作且保留输入。复制失败提供可选中的完整地址。回滚在页内确认目标版本和链接不变，支持取消；删除仍需输入完整 slug。为什么：M2 分享、M3 收反馈和 M3c 换版本都需要知道动作是否完成，浏览器原生弹窗或整页刷新会打断上下文。

**刷新保持现场。** 同一资源重新取数时保留已有内容，只标记更新中；切换作品或版本时清除上一份数据，避免串版。数据失败显示重试，不把失败写成「还没有人」。首次加载有稳定占位和可读提示。为什么：M3 的数字必须可信，等待时不能把已看到的结果收走。

**键盘和手机是同等入口。** 所有动作有可见焦点；图标按钮有名称，导航暴露当前项。对话框限制焦点、Escape 关闭、关闭后回到触发处；无脚本时仍能完成核心浏览与开始。触屏主要按钮至少 44px 高，窄屏不横向溢出，长作品名、地址和反馈可换行。遵循减少动态效果偏好。为什么：M1、M2 经常发生在手机上，P2 不能因设备或输入方式多一道门槛。

**不以视觉掩盖未实现的能力。** 没有内容就给对应的下一步；没有接通的通知、在线状态或支付不显示已完成。页面里的降级、无脚本路径与出错文案也属于验收范围，真机记录写入 `docs/spikes/`，设备模拟不冒充手机实测。

### 3.15 合集与创作挑战：让一个作品带出下一件作品

**形态分工。** 下述「窄邀请卡 + 宽反馈区」用于网页作品；文章和视频不继承窄票根比例，其作品页采用 §3.16 的阅读与观看布局。三种形态共享品牌、返回来源与零门槛约束，不强求同一个内容容器。

**邀请函的宽屏布局。** 作品页保留独立全屏，不带广场或控制台的左侧菜单：从分享链接进来的人要先认出作品并开始体验，而不是先选导航（M2b）；返回同题作品只需顶栏的来源入口。桌面顶栏与内容贴齐页面左边距，不再把整组内容锁在居中的 1040px 容器里。左侧邀请卡保持约 380–480px 的可读宽度与 16:10 封面，右侧原声与反馈区使用剩余宽度，以一条分隔线而非第二张等高悬浮卡划分。消息限制阅读行宽，输入区留在视口内，长消息流单独滚动；没有公开反馈入口时不画空面板。为什么不把卡片也拉满：长简介和开始表单不应横跨屏幕，宽屏应增加空间而不是增加阅读距离。窄于 960px 时回到单卡，反馈自愿展开为全屏；手机不增加登录、菜单或开始前的步骤。这里只调整既有反馈的布局，不承诺在线人数、实时广播或开放讨论。

**为什么要做。** M3b 不只有「作品没有观众」，还有「大家正在做同一道题，我做完了却只能丢一条孤立链接」；M3d 还需要把同一次创作的不同成果放在一起。广场由一个作品找观众延伸到一个题目或一段创作聚起作品与反馈，不变成模型评测站或泛内容信息流。看到题目 → 接触几个作品 → 自己创作 → 发布并投稿 → 分享合集 → 自愿订阅新作品，是挑战的完整环路。

**只增加一个组织对象：合集。** 普通合集是作者挑选自己公开作品形成的作品集；挑战是开放给其他作者投稿的合集，多一段题目、规则和可选截止时间。都使用 `/c/<slug>`，索引为 `/collections`。不同时建设作者主页、标签社区和赛事系统：它们的第一件事都只是把作品放到一起，先用一个对象做完整。作品本身、版本、邀请函与关注不改身份；一个作品可加入多个合集，不复制文件、不重新部署。合集创建、编辑、投稿、撤稿在开发者控制台；玩家页面只有观看、复制题目、参与说明和自愿关注，没有开发者登录或令牌。

**合集也是公开创作的组织方式。** 一个作者可把工具原型、讲制作过程的文章、独立演示视频放进同一普通合集，读者沿同一语境接触不同形态。它们各自保留版本与反馈，不把新文章当成工具的新版本；同一作品的短更新继续写版本说明。沿用合集而不新增「项目空间」「作者动态」或个人粉丝系统，是为了让 M3d 更清楚而不是多一层管理。合集只组织已明确公开的作品，不能借「展示过程」自动公开源码、提示词或隐藏作品。

**创建与治理。** 有长期账号的作者最多同时管理 10 个合集；匿名作者先发布、登录接管作品后再建立长期作品集。合集默认草稿，作者明确选择公开后才进搜索与发现；标题、说明、题目与规则是纯文本，有长度上限。普通合集仅主人可以添加自己的作品；挑战可由其他长期作者提交自己的作品，组织者能移除，投稿者能随时撤回。每个合集最多 200 件，同一作品只有一条投稿。被组织者移除的作品不能反复重投；组织者可以解除限制。运营者可隐藏有问题的合集，隐藏后不能靠作者重新公开恢复。不能冒用别人的名字把别人作品写成自己的投稿。

**投稿不是偷改公开状态。** 只接收已发布、作者主动公开、未到期、未隐藏且无需口令的作品；拒绝临时隧道与匿名到期链接，不承诺把这些链接变成永久档案。退出公开、隐藏、删除或到期时，作品及其创作说明从所有合集、搜索、相关作品和摘要中消失；关系可以保留，不能泄露私密内容。合集下架也会停止接受投稿和发送摘要。截止后保留仍有效的公开作品，停止新增及替换投稿，撤回仍可用；没有「已结束」却还能投稿的假状态。

**比较诚实。** 创作说明可填写作者附言，为作者自述，不认证作品属性。记录投稿时的作品版本；当前体验仍是作品当前版本，更新后明确显示「投稿 vN · 当前 vM」，不把最新文件假装成原始参赛版本。本版没有冠军、奖金、评分与排行榜。

**玩家页面。** 保留现有克制的深色侧栏与作品卡；侧栏增加「合集」，因为它直接缩短找同题作品的路径。广场标题行右侧提供可直接提交的紧凑搜索，手机另起一行，接着少量最新公开挑战入口、作品流。合集页从上到下是标题与组织者、简介和状态、题目与规则、参与说明/分享/关注、作品墙。复制失败时保留可选中的原文；分享优先使用系统分享，不可用则复制当前地址，失败明确提示。无脚本仍可搜索、筛选、翻页、看规则、打开作品及用邮箱关注。卡片不同时运行用户作品，不创建自动播放墙。作品邀请函顶栏常驻品牌字标与返回来源入口（← 返回合集/广场），去除易造成目标分散与视觉割裂的轮播切换，将注意力纯粹留给当前作品体验；原作品链接无需先经过合集，不注入作品画面。所有玩家页面均不增加登录、安装或额外必经跳转。

**搜索与热度。** 搜索只查公开快照中的作品标题、简介、创作者、合集名称与说明，支持作品形态筛选。结果明确分成合集与作品，没结果可清空条件，地址保留条件与分页。默认保留时间流；跨形态的「近 7 天」按作品打开会话的共同口径去重，不把它称为认证真人、内容质量或模型能力，不按观看时长压过短文章。现有网页开始计数不等于这个访问口径，不能只换标签；新口径未采集完整前按时间兜底，不补造历史数字。私密、隐藏、撤回的作品与过程不入索引，推广不购买搜索或热度排名，每页数量有上限。

**回访。** 关注对象增加合集，仍用已有的自愿邮箱确认与根域 `pt_me`，玩家不注册。合集关注是每周新投稿摘要，不是每一件作品触发一封信，也不拿作品更新冒充新投稿；没有新的有效作品就不发，截止本身不触发营销邮件。关注页可以打开合集、取消订阅；退订、隐藏及投稿撤回都作用于摘要。未关注前的新投稿不补发，队列按合集、玩家和周次防止重复。只展示实际开放的邮件渠道，不给只有推送的订阅者一个永远收不到的合集关注。

**开发者工作台。** 增加「合集与挑战」：我的合集、可参加的挑战、建合集、编辑资料与公开状态、添加已有作品、填写创作说明、移除/撤回、复制玩家链接。发布作品仍走原 CLI/MCP；控制台选择已有作品投稿，题目说明给出现有发布命令和合集标识，不再增加一套上传器。错误落在发生的表单里，保存中禁用重复提交，成功后刷新真实结果；删除和组织者移除明确说明影响，不删除原作品。

**冷启动与成功标准。** 不往生产灌假用户、假投稿或假数字；本地示例单独标为演示。运营先组织一场真实挑战，以邀请卡和社群带来第一批参与者。关注的是由题目带来的新发布、同合集跨作品体验和下次回访，不承诺做完功能就有人来。所有「已验证」必须对应新增的带日期 spike；桌面浏览器、本机移动视口、真实手机和线上邮件分开记录，未跑的不算完成。正式运营仍要真域名、真实种子作者、移动网络与邮件投递验收。

### 3.16 作品形态与首批交付边界

**展示原则：卡片负责分发，作品页负责内容。** 广场、合集、群聊分享里的卡片只帮助体验者判断「谁做的、是什么、要不要打开」；文章正文与视频播放器不塞进这些缩略卡。进入 `/p/<slug>` 后按作品形态切换布局，而不是所有形态都沿用网页的窄票根。网页保留 §3.15 的左侧邀请卡；文章成为阅读页，视频成为观看页，内容占据主要宽度，反馈退到辅助位置。这使 M2b 更快进入内容、M3 的反馈有上下文，不新增页面层级或发布对象。

**入口与标签页。** 卡片的主链接在当前标签页直接打开作品页；文章不先到摘要卡再点「阅读全文」，视频不先到邀请卡再点一次「开始观看」。视频播放按钮只是用户授权播放，不是第二次导航。允许用户用浏览器原有方式另开标签，但平台不默认弹新标签，也不把正文或播放器放进遮罩弹窗；长文的刷新、链接分享、浏览器返回与视频状态不应依赖临时浮层。作品页保持完整地址与原来的访问边界，不加登录、安装或必经跳转。

**文章：正文就是主角。** 分发卡显示标题、作者、形态与至多两行作者摘要；没有摘要时可用正文首个可读段落的纯文本节选，不凭空生成卖点。卡片不嵌入可滚动正文。进入作品页后一次呈现完整的受限正文结构，不做折叠截断或「展开全文」。首屏顺序是文章标题、作者与版本日期、可选的一两行摘要、正文；邀请口吻压缩到作者署名，不另占大块票根。正文第一个一级标题与作品标题相同时只显示一次。封面在分享卡可用，在阅读页不是必需的首屏巨图；无封面时不生成大占位字卡，正文配图保留在作者安排的位置。正文栏约 680–760px，桌面 18px、手机 17px 起、行高约 1.85，以真实中文、图片、代码与表格验收；代码和宽表局部横向滚动，不把整篇文章放进卡内滚动框。背景沿用克制的中性主题，正文区去大圆角、阴影与票根切口。纸感浅底仅作为设计对比方案，首批不因此增加阅读偏好设置。

**视频：先看画面，再看资料。** 主内容区顶部直接给播放器，封面只作播放器海报，不再在播放器上方重复一张邀请封面。播放器使用主要列宽，普通横屏约 16:9；竖屏或非标准比例保持原比例，以留边而非裁切适配，画面高度不压过整个首屏。标题、作者、版本与简短说明放在播放器下方。用户主动播放，不自动播放、不连播、不悬浮跟播；沿用浏览器原生播放、音量、进度与其实际提供的全屏能力，不引入播放器库，只为外观重写控件没有准入理由。未生成缩略帧或未知时长时留空，不伪造截图、播放量、清晰度选择或时长；加载和失败要在播放器附近明说，不把播放按钮永远挂在坏海报上。

**反馈与专注。** 文章与视频使用「主内容 + 次要反馈栏」，不能沿用窄卡配超宽聊天区的比例。大桌面（从 1280px 起验收）反馈栏约 320–360px，靠右以细线分隔，消息流独立滚动；主内容沿页面左侧展开，文章只限制文字阅读宽度，不把整个页面重新缩成居中卡组。默认不让动效、贴纸或未读角标争夺正文与画面。既有公开入口存在时，提供可逆的「专注阅读 / 专注观看」开关隐藏反馈栏，恢复后保留内容位置；视频不因切换布局而重建或暂停。没有公开反馈入口就不画空侧栏。小桌面和手机优先单栏：文章直接可读、视频直接可播，反馈通过明确按钮自愿展开，关闭回到原滚动位置。无脚本时仍能读完整文章、播放视频与通过普通表单反馈，专注开关仅为增强。

**反馈属于正在看的内容，不是通用聊天室。** 文章提示「哪一段需要说得更清楚」，视频提示「哪一处节奏或画面值得调整」，沿用真实版本与作者请求，不对文章和视频展示游戏手感类贴纸。首批先保证原有纯文本反馈与可选公开原声，不为版式改动宣称已有段落批注或时间码跳转。后续若加入引用选中文本、携带播放位置等能力，要同时设计版本变更、定位失效、公开可见性和无脚本退路，再另行验收；不显示尚不可用的入口。

**验收与失败形态。** 设计稿不算实现或手机验收。进入首批发布前分别检查：文章正文首屏可见、标题不重复、长文/配图/代码/表格无页面溢出；视频首帧与弱网恢复、原比例、拖动、横竖屏及原生全屏；内容与反馈切换时不丢滚动或播放进度。文章失败保留标题、作者和明确的重试方式，配图失败不隐藏正文；视频失败保留作品资料并给出能执行的重试提示，不改成无法兑现的「正在处理」。未经实际采集不能展示读完、看完、阅读时长或观看人数。

**同一套作品身份，三种明确的交付。** 形态用于决定怎样打开、怎样称呼、哪些事实可观察，不是三个独立平台。以下是目标输入契约，不是现有 CLI 能力声明；帮助与机器接口只在实现及验收后公布对应入口。

| 形态 | 首批输入 | 体验者如何接触 | 不做或失败时怎样说 |
| --- | --- | --- | --- |
| 网页 | 原有静态目录、本地端口、带后端目录 | 邀请函进入或原有纯净子域直达 | 保留导出物检查、响应头、离线与限额提示，不为了新形态重写网页 |
| 文章 | 一份 UTF-8 `.md` 原稿（最多 1 MiB）与它显式引用的同目录树内 PNG / JPEG / WebP / GIF；同一个发布命令直接接收原稿文件 | 邀请函同页显示正文，可直接阅读与反馈；首个一级标题作作品名，没有则用文件名 | 不执行原生 HTML / 脚本、嵌入组件或用户插件；不抓远程图片，不接受越出原稿目录的路径；图片缺失、字节与格式不符、正文过大明确报错 |
| 视频 | 恰好一份 `.mp4`；容器内每条视频轨为 H.264，音轨若存在均为 AAC；同一个发布命令直接接收视频文件 | 邀请函同页标准播放器，用户点播、拖动、暂停 | 不把后缀当编码验证；不支持的容器 / 编码、超限、损坏明确说明，不靠改后缀或后台偷偷转码继续发布 |

视频基线参考 [MDN 的媒体容器与编码说明](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Containers)。它是选择基线的依据，不代替我们的手机、网络与实际播放验收，也不等于所有 MP4 都可播放。静态 HTML 文章仍可按网页目录发布，不把它自动识别成原生文章或宣称已有阅读器。

**原件、展示与安全是三件事。** 文章在发布时通过平台维护的受限渲染器生成展示产物，原稿与衍生产物分别按内容哈希保存；原有网页与视频原件不改写。根域只渲染经过安全处理的正文结构，不信任上传的任意 HTML，不执行作者代码；Markdown 内的原生 HTML、危险链接协议和远程嵌入不进入首批能力。只打包允许范围内、明确引用的本地资源，不顺手上传整个工作目录，也不在服务端抓取任意外链。文章原稿不从作品子域公开分发，正文配图通过当前作品清单读取；视频原件只作为同页播放器的媒体源，经当前作品权限、额度与 Range 路径交付，不另开可绕过边缘的存储下载地址。

**每种都要走完发布后的事。** 标题、作者、当前版本、版本说明、邀请卡、可选封面、反馈、关注更新、公开选择、撤下、回滚、删除与额度是共同契约。分发卡没有封面时使用既有字卡，但不把字卡强制插入文章首屏或视频画面；不依赖截图或抽帧才发布，不为接文章和视频先建设剪辑器、图床或视频转码集群。作品主形态保持稳定，跨形态改变需要作者明确创建另一作品并用合集关联，不能静默改变关注者下一次会收到什么。

**读取按需，开销可见。** 文章正文与配图、视频原件与展示产物都计入对应存储与传输预算。视频请求支持范围读取与取消传输，不为播放几秒先把整个文件读入内存或下载到边缘；不自动播放、不预取整段视频、不连播下一件。上传显示实际阶段与进度，文章 / 视频的大文件不套用小目录「几秒发布」的口号。限额、网络失败、未支持编码都必须有可读的收尾。

**暂不延伸。** 音频、PDF、幻灯片、图片集等不是被永久排除，但不因叫「多形态」就列入首批已支持清单。下一种形态仍要证明能缩短 §1.2 的时刻，定义零门槛打开、具体反馈与成本边界，再实现、真机验收；不先堆格式选择器或空页面。

### 3.17 长文与小说连载：同一作品里的持续阅读

**为什么不是把合集改名为小说。** 连载要让读者按作者安排的顺序读下去、在下次更新后回到正确位置（M2b、M3c），而合集是可撤回、可混排、可跨作者的作品组织。一本连载应是一个文章形态作品，拥有一个稳定 slug、作者与关注关系；章节是作品内部的稳定内容单元，不为每章创建独立作品、关注关系或一张广场卡。普通文章继续是单篇，不强制作者建书或填章节字段。

**分批落地，不假装已有出版系统。** 当前先交付文章 / 视频的新布局、文章本文目录、专注模式、明确失败提示和仅此浏览器的阅读位置。这些直接缩短长文阅读与回访路径，也是后续单章阅读器的基础。目录项只是本篇的小节，不称章节；不把长文切片或二级标题冒充连载发布。真正的章节清单、发布接口、章间导航和章节更新通知必须在同一批端到端实现中交付，未完成前不出现建书、发布章节、上一章 / 下一章等空入口，CLI / MCP 不声称支持连载。

**章节身份与版本契约。** 目标模型在文章形态下增加有序章节清单，每章有不可因改名或重排变化的 `chapter_id`、标题、发布状态与独立内容修订号；书的清单修订号负责目录顺序、书名和章节引用的原子更新。现有 `Manifest.version` 仍是作品发布修订，不能把它直接叫章节号。发布只引用已校验且完整可读的正文产物；不能先露目录再上传正文。草稿不出现在公开目录、搜索、阅读位置提示或通知里。章节删除 / 撤下 / 回滚不复用旧标识；已分享但不可访问的章节地址说明原因并给出返回目录入口，不能静默跳到另一章。

**打开与读下去。** 未来的 `/p/<slug>?chapter=<chapter_id>` 直接进入指定已发布章节，地址刷新、分享和浏览器返回均可用；指定章节优先于本机记忆，没有合法章节参数时才给可自愿选择的继续阅读入口。书入口第一次打开就展示第一章及可展开目录，不先过书籍介绍卡或登录。标题区轻量呈现书名、当前章节与目录；正文仍是舒适行宽，章末才出现上一章 / 下一章 / 返回目录。最新一章结束后只显示真实的连载 / 完结状态和自愿关注，不显示不可点击的下一章、不自动把读者送去别的书。更新不会在正在阅读时自动换章或改正文。

**续读与隐私。** 当前单篇文章以作品 slug、内容修订和小节锚点记录本机位置；仅保存位置和必要版本信息，不保存正文或读者输入，不当作登录或服务端“读完”统计。首次打开不自动跳页，有有效记录才出现「继续上次阅读」；带明确锚点的链接优先。同版本可以回到该小节内的位置；版本变更时仅在稳定小节仍存在的情况下提供带“内容已更新”说明的续读，不复用旧百分比强行跳转，小节消失则从头阅读。浏览器存储被禁用、损坏或达到容量时不挡正文，明说无法保存；可清除当前作品位置。未来扩展为 `slug + chapter_id + chapter_revision + anchor`，阅读位置与书的目录修订分离；跨设备同步另需自愿身份方案，绝不成为开始阅读的条件。

**反馈与追更。** 连载的反馈必须携带真实章节标识和章节修订号，不能把对第三章的意见挂到书的最新章；剧透内容默认不跨章展开，作者选择公开时仍保留所属章节。发布新章节与修订旧章节区分事件：追更针对新增可读章节，修错字不伪装“更新了一章”反复通知；同批发布合并通知，失败可重试且不可重复投递。沿用作品关注入口，不增加强制书架、打卡、阅读任务、催更榜或付费门槛。首批不建设打赏、付费章、编辑器或复杂字体主题面板。

**真正连载的上线门槛。** 需要真实发布、重排、改名、修订、撤章、回滚和原子目录验收；旧链接与旧书签不串章、不泄露草稿；新章通知按发布事实去重；反馈对准章节版本；手机长读、软键盘、返回、弱网和跨版本续读分别记录。本文是目标契约，不以当前单篇阅读器验收替代连载功能验收。

## 4. 架构：从产品倒推

### 4.1 一个主域，不同信任来源

- `playtest.run`：广场、合集、关注、作品邀请页、账号、`/console/` 管理与文档、`/v1/` API。一个产品入口，一份账号，公开访问不需要登录。
- `<slug>.playtest.run`：作品原件、网页运行、隧道和同源 SDK。每件作品使用独立源根目录；根域不执行作者上传的脚本。平台 API 只在精确根域提供，不能靠同一路径从作品子域访问管理服务。

**为什么暂不增加运行域。** 用户先记住一个品牌地址，现有作品仍能直接体验。独立可注册域能提供更强的同站隔离，但本轮选择单域的认知成本与部署范围。不同源不等于不同站点，不能仅靠 SameSite 阻止兄弟子域请求。这个取舍不取消 host-only 凭据、精确 Origin、响应头过滤和根域脚本限制。

**会话与发布凭据。** 网页会话单独保存在 browser_sessions，明文仅进入 HttpOnly Cookie；HTTPS 用 `__Host-pt_session; Secure; HttpOnly; Path=/; SameSite=Lax`，没有 Domain，本机 HTTP 用 `pt_session`。会话有效期 30 天，多设备分别签发，退出只撤销当前会话。API 令牌放在独立 tokens 表，不能冒充网页会话，网页会话也不能当 Bearer 令牌。网页写请求校验精确平台 Origin，作品子域与无 Origin 的 Cookie 写请求均拒绝；CLI 的独立 Bearer 请求不依赖 Cookie。

**运行源不接触平台权限。** HTTP 和 WebSocket 隧道都剥离平台会话、OAuth 状态 Cookie 与平台内部 Cookie；上游不得设置平台 Cookie 或逃出作品主机的 Domain Cookie。OAuth 使用绑定发起浏览器的 HttpOnly 状态 Cookie、短时 state 与一次性交换；回程只接受本站相对路径。根域页面限制脚本来源，管理页面禁止嵌入；包含邮件令牌的入口不向子资源发送 Referer，GET 预览不消费登录令牌。

**公开读取与账号服务分开。** 作品、广场、合集、邀请卡与权限快照由边缘从私有对象存储读取。登录、私有管理、关注查询与写入由 API 提供。控制面故障不必让已经发布的作品一起下线；个人状态与写操作则如实提示不可用，不把取数失败显示为空列表。账号响应不被共享缓存。

泛域名证书覆盖根域与一级作品子域；slug 仍只能一级。公共地址不再使用另一个平台根域，不为旧数据或旧链接增加迁移分支。

### 4.2 上传路径与 S3 主存储

**这是已决定的目标，不是已迁移的声明。** 2026-09-12 的只读核对记录在 `docs/spikes/2026-09-12-storage-backend-audit.md`：当时生产 API 与边缘共用服务器 ext4 目录，仓库为 `FsStore`。接入真实 S3、迁移已有作品与恢复能力尚须分别验收；写出一层抽象或跑过本机模拟不算生产切换。

**「全面 S3」只指作品物料的生产持久层，不指所有业务状态。** 原稿、视频、网页文件、配套资源、封面、衍生展示产物和版本清单由私有对象存储持久保存；账号、权限、关注、反馈与用量继续放关系库。生产物料不能只在 API 与边缘共享目录中存一份；本地盘可留临时文件、可重建缓存，数据库自身的磁盘与备份不在这个替换范围里。本机开发与测试可保留文件系统后端，生产配置不能在 S3 不可用时静默降级为本地盘并仍报告成功。

```
CLI / MCP：识别输入与配套资源 → 检查并计算内容哈希 → 获得上传授权 → 上传缺失对象 → 校验 → 提交版本
控制面：确认对象完整 → 写不可变清单 → 发布当前指针与读取快照 → 报告成功并安排通知
边缘：先检查作品权限、到期与额度 → 路径映射为对象 → 缓存或 S3 按需读取 → 作品域名交付
```

**为什么现在做。** 视频与连续版本会扩大文件体积、读取量和留存范围；继续让读写共享一台机器的路径，会把这些产品能力绑在单机容量与升级上。S3 是持久层，边缘仍是访问与成本边界；不把「存得下」当成「播放得好」，也不要求为迁移同时换数据库、整个云平台或部署体系。

**存储契约，不模拟远程文件夹。** 保留内容寻址的 `blobs/<前两位>/<hash>`、`sites/<slug>/manifests/<version>.json` 与当前指针的概念；对象读取、范围读取、写入、条件更新、列举与回收通过存储接口完成，不把本地 `Path` 或原子改名当成 S3 能力。上传初期可沿用受控 API 流式写 S3；大文件须有有界内存、分段与失败重试设计。将来直接上传也只能拿到短期、限定对象与操作的授权，不能向 CLI 或体验者发桶级密钥。

**提交不暴露半成品。** 先确认完整字节、大小和内容哈希，再写版本清单与更新当前指针；失败时继续保留旧的可用版本，不发送新版本通知。S3 的 ETag 不能普遍当成文件内容哈希，尤其不能拿分段上传结果替代我们自己的内容校验。数据库与对象存储之间不假装存在一个共同事务，部分成功要能识别、重试、对账；并发发布不能让较旧结果覆盖更新的指针。具体协议实现时以官方 [分段上传](https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html)、[校验和](https://docs.aws.amazon.com/AmazonS3/latest/userguide/checking-object-integrity-upload.html) 与 [条件写入](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html) 语义为准，并在所选后端验证。

**源站私有，体验路径不变。** 不开放桶，不把作品 URL 重定向到可绕过限额的 S3 直链；玩家路径仍只用现有内容域，控制台与凭据仍只在创作者域。命中缓存也先做作品权限、到期、撤销与额度判断；视频 Range、文章配图与封面同样计量。不把对象键不可猜当成访问控制，不让跨作品去重复用变成跨作品读取权限。

**缓存与故障是产品的一部分。** 不可变对象可按哈希缓存；当前指针、权限、公开历史、合集与广场快照必须有明确失效策略。用户 URL 仍需重新验证版本，不能因路径不变而拿到混合的新旧文件。源站不可用时，已有且能确认仍允许访问的缓存才可继续用；缺失缓存显示服务暂不可用，不能伪装成作品被删或返回半段成功内容。无法确认访问权限时拒绝交付，不用可用性越过私密与撤回边界。

**回收与迁移不丢作品。** 垃圾回收只删除不被有效版本引用、也不属于正在上传任务的对象，保留安全等待期；共享 blob 不随单一作品删除而误删。清理未完成分段上传，不用简单按 blob 创建日期过期的规则删除仍被引用的作品。先复制并校验已有对象和清单，在真实域名核对旧链接、回滚、配图与视频读取，再切读取和写入；过渡期明确唯一写入源与回退路径，保留旧数据直到迁移、回退与恢复验收完成，不做无期限双写或切完就删盘。

**区域与兼容性只承诺测过的。** 目标是靠近现有香港边缘的对象源；先选一个实际 S3 后端与区域跑完整路径，再决定其他兼容服务。接口叫 S3 兼容不代表所有行为一致，不同时承诺兼容全部供应商；真实移动网络测试覆盖首屏、播放开始、拖动、失败恢复与持续下载（§4.4、§8）。

**已有网页能力不降级。** Wasm MIME、预压缩 `.br` / `.gz`、COOP / COEP、SPA 导航回退与 Range 继续按现有作品规则提供，隧道响应体仍不改写。上传前检查网页入口、引擎资源缺失与预压缩配置；文章检查正文与资源边界；视频检查容器、编码、大小与完整性。失败用第一次使用者能懂的话说明，不用一个「S3 出错」覆盖所有原因。文件大小、版本数、存储、读取与传输按 §6 约束。

### 4.3 隧道路径

要求：从开发者机器只出不进；走 443 且看起来像 HTTPS；一条连接上复用很多玩家连接；WebSocket 原样过；断了自动重连；边缘要能计量；不依赖用户机器上有 ssh。

**v0.1 用 WebSocket over TLS + yamux 多路复用**；QUIC 留给 v0.2（UDP/443 在一部分网络被掐，必须保留 WSS 回退）。`ssh -R`、裸 TCP、HTTP/2、WebRTC 直连各自的淘汰理由：依赖系统 ssh 且计量做不了；公司代理只放 CONNECT；只有客户端能开流而方向反了；浏览器侧要 Service Worker 配合且复杂度高。

边缘按 Host 找到隧道会话，开一条 yamux 流，把请求以 HTTP/1.1 写进去，把响应流回玩家；101 之后双向拷贝字节。默认把 `Host` 改写成 `localhost:<port>`（Vite 6.0.9 之后默认只放行 localhost），原值放 `X-Forwarded-Host`；检测到 Vite 时打印 HMR 那一行配置。

**响应头在隧道路径上也补；响应体一个字节不动。**

生命周期：CLI 退出或电脑休眠即离线，门禁页显示离线与上次在线时间；重连 1 s → 30 s 指数退避加抖动；一个 slug 同时只绑一条隧道，新的挤掉旧的（旧连接收到关闭码 4001，旧令牌进驱逐名单，重连一律 409）；离线判定在边缘（20 秒一个 ping，60 秒没帧就离线）；令牌活不过作品。

**上传与隧道混合**：`playtest ./dist --backend 3000`，先匹配静态文件与目录索引；启用 `--spa` 时导航请求可以回退到 `index.html`；仍未命中才经隧道到开发者机器。不是强制 `/api/*` 前缀，也不把所有 WebSocket 请求声明为无条件优先。后端离线时清单外的路径回 `503` 加 JSON（`backend_offline`），不是一页 HTML。

隧道不适合的场景要在 CLI 里说出来，而且要算出数字：「你这个目录 32 MB，隧道模式下一个玩家大约要等 45 秒，十个人同时进来会更久。建议 `playtest ./dist`。」

### 4.4 边缘放哪

玩家和开发者在哪，边缘就在哪附近。第一批用户在大陆，边缘放**香港**：不需要备案，是大陆玩家能直接到的最近的境外。这是工程手段不是卖点，文案里不出现地理。

延迟不是地理决定的，是回程线路决定的：同样标称香港，CUG / CMI 优化线全国三网平均 34–56 ms，普通国际回程 194–319 ms 且绕美欧。「大陆到香港 30–60 ms」是压测的验收目标，不是事实。选云之前压一周：三网 × 两个城市 × 家宽与 4G × 白天与晚高峰 × 微信 WebView 与系统浏览器，记 p50 / p95 / p99、丢包、30 与 100 MB 持续下载、traceroute。结果进 `docs/spikes/`，此前本文不出现供应商名和毫秒数。第二个区域等有那边的用户再加。

### 4.5 控制面

`playtest.run`，一个关系库（v0.1 SQLite，出现第二个写入节点再换 Postgres）：用户、slug、版本、对象清单、隧道授权、会话、反馈、用量；这一版新增**玩家、关注、通知、推广、名额与留名**。四类客户端：CLI（设备授权）、控制台、边缘（写方向）、管理接口（运营者，令牌鉴权）。

**控制面发布对象快照、边缘从 S3 读快照**，这是两者之间的内容读路径，不再要求共享本地文件目录：

| 文件 | 内容 | 什么时候重写 |
| --- | --- | --- |
| `sites/<slug>/manifests/<version>.json`、`sites/<slug>/current.json` | 不可变版本清单与可变当前指针，含作品形态和展示产物引用 | 成功提交版本、回滚；不是重写旧清单 |
| `sites/<slug>/live.json` | 这个作品**会变的那些**：名额与已加入人数、关注数、群链接、反馈是否公开与最近三条公开反馈、开发者头像地址 | 有人留名、关注变化、开发者改设置、反馈被公开或隐藏、每 5 分钟 |
| `plaza.json` | 广场的全部内容：作品（含封面、头像、7 天人数、关注数、名额进度、求测、到期）、推广中的作品与窗口、关注广场的人数 | 公开 / 撤下 / 求测变化、新版本、推广上下线、每 5 分钟 |
| `capabilities.json` | 控制面现在能做什么：邮件是否配了、Web Push 的公钥 | 控制面启动 |

公开版本说明与合集也通过受权限约束的读取快照交付，不能为了展示过程把私下反馈或草稿清单整个复制到根域。物料在 S3，业务关系仍在数据库；对象桶的版本保留不替代作品版本、用户权限或应用回滚。

为什么不让边缘查库：边缘不认识控制面是这里的第一原则——控制面挂了，作品与广场照常，只是数字旧几分钟。

**边缘写给控制面的**：第一层事件每 60 秒批量（不变）；**关注登记、确认、退订同步转发**（玩家在等一句「确认信已发」）；留名跟着 `start` 事件一起走（名字是事件里的一个字段）。

**新增的表**：`players`（邮箱或推送订阅，确认时间，退订令牌）；`follows`（玩家 → 作品或广场，来源，时间）；`notifications`（待发队列、发送时间、渠道、结果——每作品每 24 小时最多一封在这里判）；`boosts`（作品、SKU、窗口、状态 pending / live / ended / rejected、是否赠送、订单号）；`sessions` 加 `name` 列；`sites` 加 `seats`、`community_url`、`feedback_public`；`feedback` 加 `public` 列。

**管理接口**（`/admin/*`，`PLAYTEST_ADMIN_TOKEN` 鉴权）：赠送 / 审核 / 撤下推广；手工撤下广场作品；看通知队列。运营者用 `scripts/admin.sh` 调它；控制台里的管理页后置。

### 4.6 SDK

`playtest.js`，几 KB，无依赖：捕获错误、加载用时、自定义事件、反馈按钮；只往 `playtest.run` 发，不种第三方 cookie。脚本由边缘在作品自己的域上同源提供（`/_playtest/sdk.js`），开发者加一行 `<script>`。

**反馈提交后的那一屏是玩后的落点**——这是作者自选 SDK 带来的网页内能力，不是平台偷偷注入的社交层。上面三样：「谢谢」；「有新版本时告诉我」（实际开放的邮箱或浏览器通知）；「看看别的作品」。没接 SDK 的网页内不增加控件，体验者仍可在作品邀请函反馈与关注。文章阅读器和视频播放器使用平台自身明确的反馈入口，不要求作者给 Markdown 或 MP4「加一行脚本」，事件同样遵循 §3.5 的边界。

### 4.7 语言与实现选择（2026-09-07 已定：Rust）

CLI、边缘、控制面都用 **Rust**，一个 Cargo workspace（`cli/`、`edge/`、`api/`、共享类型在 `common/`）。控制台与 SDK 是 TypeScript。为什么不是 Go：两个都对，创始人的判断是**开发成本不是约束，要体验和健壮性更好的那个**，且团队近期手感在 Rust 上。

边缘 TLS：**前置 Caddy**（带 Cloudflare 插件，DNS-01 签泛域名证书，`deploy/`），边缘进程只说明文 HTTP；DNS 放 Cloudflare 但只做解析不做代理。本机开发阶段边缘走明文，Chrome 与 Firefox 把 `*.localhost` 当作安全上下文。

### 4.8 滥用与安全

公网托管用户内容天生是钓鱼与恶意软件的渠道。分层：

- **服务端不运行用户代码**，但仍需处理钓鱼、恶意文件、版权与隐私举报；不把这个边界误说成内容安全已自动解决。
- 创建长期作品要通过邮箱或 GitHub 登录；匿名链接只活 24 小时、带角标、限流量。每账号活跃 slug、月流量、并发玩家有上限；匿名身份签发先有持久化的每分钟平台保险丝，接入可信反向代理来源后再叠加逐来源限制，不把全平台上限冒充精确反滥用。
- **内部事件与上传不是公开写入口。** 边缘每 60 秒上报事件时携带只存在于部署环境的 `PLAYTEST_EDGE_INGEST_TOKEN`；没配时边缘拒绝以连接控制面的方式启动，控制面也拒绝无凭据或错凭据。blob 只有在哈希与大小都属于同一作者一小时内尚未提交的准备清单时才接收；每个作者最多同时保留 8 份准备记录。为什么不是只靠 CORS、作者令牌或对象哈希：`Origin` 可以伪造，作者令牌不代表可以往任意哈希写 200MB，内容寻址也不自动给字节建立所有权。
- **额度是双重上限**：月配额挡长期滥用，**每 slug 每小时流量熔断**挡 DDoS——在边缘本地判定，超限把 slug 转成一页静态说明。
- 邀请函说明作者、形态与版本，但不是平台背书，不靠给文章或视频多加一次点击制造安全感。
- slug 黑名单；举报 → 下架 → 令牌撤销 → 边缘立即断。
- **广场**：只有开发者主动公开的作品会上去；24 小时内 3 个不同会话举报即自动撤下；封面走那个 slug 的每小时熔断；根域页面不出用户的任何可执行内容；**推广位上的作品先人工看过**。
- **关注**：邮箱双重确认，没人能替别人订阅；登记接口按来源令牌桶限速；每封信带一键退订；发信域名配 SPF / DKIM / DMARC；退订与投诉率进运维看板，超阈值自动停发并告警——发信信誉是这条环的命。
- **留名**：名字过一遍脏词表与长度限制；开发者可以在点名册里隐藏任何一个名字；公开反馈里的名字同样。
- **推广**：匿名不能买；先审后上；付了钱被拒全额退。
- 平台会话与不受信任的作品源保持权限边界（§4.1）；管理接口只在平台根域、令牌鉴权。
- 隧道模式提示开发者：暴露开发服务器等于暴露源码和 `/@fs/` 这类接口。

文章按 §3.16 进行受限渲染，视频上传不执行任意处理命令；文件类型与大小校验、配套资源边界、内容举报、公开过程撤回覆盖全部作品形态。创作来源与提示词是自愿自述，不认证版权归属、原创程度或模型能力。私有 S3 的授权、密钥保管、短期上传凭证与缓存撤销也是上线验收范围，不能只保护邀请函而留下可直接下载的受限原件。

### 4.9 邀请卡的渲染

由**边缘**渲染：它手里有清单、封面 blob 和 `live.json`（名额），`/_playtest/card.png` 与 `/_playtest/card-wide.png` 按当前版本出图，`ETag` 跟版本与名额走，边缘本地缓存。渲染路径：拼一张 SVG（版式、文字、二维码矢量、封面以嵌入图引用）→ `resvg` 光栅化为 PNG。**中文字体**从系统读（`fontdb` 加载系统字体目录），服务端镜像装 `fonts-noto-cjk`，本机开发用系统自带的中文字体；不把字体编进二进制（十几 MB，且任何标题都可能用到子集之外的字）。二维码用 `qrcode` crate，内容是作品链接加 `?from=card`。渲染一张卡的目标是 100 ms 以内、一次渲染多次命中。

为什么不在 CLI 本地渲染：CLI 拿不到玩家侧的名额进度，且要在三个平台上处理字体；为什么不在浏览器 canvas 里画：匿名用户没有控制台可去，agent 路径要的是一个文件。

### 4.10 通知的投递

**邮件**：控制面里一个发信抽象，三种实现由环境变量选——`log`（仅本机预览，不算投递）、`resend`（托管版）、`smtp`（自托管）；部署默认 `off`，没有配置服务商时不向玩家提供邮件关注，不能用日志模式冒充发送成功。发信域 `notice@playtest.run`，DNS 上配 SPF / DKIM / DMARC（Cloudflare，创始人操作）。**每个作品每 24 小时最多一封**在入队时判：同一作品 24 小时内已有一封已发或待发，就更新待发那封的正文而不新建。周报周一 09:00 Asia/Shanghai 由控制面里的定时任务生成。

**邮件也是玩家路径的一部分，不是调试输出。** 它服务 M2b「敢点开」与 M3c「下一版还有人来」。正文中文，一份内容同时生成 HTML 与完整纯文本；不是在裸链接外面套一个 logo。固定发件人显示名 `playtest.run`；主题先说作品与动作，收件箱摘要补充这封信的用途，不把验证令牌放进摘要。版式是窄幅单栏、清晰字级、留白与细分隔线，黑白为主，只有一个主行动。为什么不是照搬网站的深色大封面：邮件首先要在图片被拦、样式被裁剪和手机窄屏时仍读得懂；不依赖图片、远程字体或脚本，不加追踪像素，也不把普通的纯文本邮件等同于低垃圾邮件率。

四种用途分别写，不套一段「点击这里」：
- **确认关注**：说清关注哪一个作品、确认后才生效、开发者看不到邮箱；按钮「确认关注」。明确请求的新作品周报沿用此确认流程，不顺带订阅。
- **换设备找回关注**：按钮「找回关注」，不使用「登录 / 注册」；和确认信一样说明链接 48 小时内有效、仅可使用一次、不要转发，非本人操作可忽略。
- **作品更新**：作品名与版本在标题，开发者的原话单独成段；未写更新说明就如实说明，不编造改动；按钮直达玩家侧邀请函。说明收到邮件是因为关注了这个作品。
- **已有周报**：作品逐条分开，推广仍明确标识；没有新内容不发。模板覆盖现有渠道不构成新增周报入口。

每封 HTML 邮件保留可复制的主链接，纯文本提供同一个行动与同一个地址。页脚给「管理关注」与「一键退订全部关注」；后者目前会取消所有关注与浏览器通知，不能写成只退订当前作品。标题、开发者文案都按不可信文本转义，模板只把配置的玩家域地址变成可点击链接，不引入开发者控制台域。模板预览必须复用实际投递的渲染器。浏览器预览、服务商接受、收件箱送达是三个不同结果；上线前仍需真实 Gmail / QQ / 163 收件、链接往返与退订记录，未完成就不宣称邮件已经验收。

**Web Push**：VAPID 密钥对在控制面第一次启动时生成并存进数据目录；公钥经 `capabilities.json` 给边缘、再给门禁页；订阅对象存 `players`；发送用 `web-push` crate；订阅失效（410）即删除。iOS 只对加到主屏幕的站点生效，门禁页按能力检测决定显不显示这个按钮。

**失败形态**：邮件服务商不可用时，登记照常成功、确认信进队列重试，玩家看到的是「确认信稍后送达」，不是报错；发送失败三次进死信、运维看板可见。

## 5. 大陆特有的现实

- **微信是分发渠道，不是浏览渠道。** 《微信外部链接内容管理规范》（2025-10-23 生效）§2.5 把「H5 游戏、测试类内容」列为常见违规情形，§2.18.4 把未备案、难以追溯运营者的链接列为风险，§3.2.2 把多域名规避列为对抗，§3.2.3 把「微信内展示与其他浏览器实质性不一致」列为对抗。实际执法多针对病毒营销 H5，但规则文字给了腾讯全部裁量权。**所以「微信里点开就能玩」是待验证假设，不是承诺**；文案写「为微信分享优化」；发布前用真实微信账号在 Android ≥ 6 台、iOS ≥ 4 个系统版本上测私聊 / 群聊 / 朋友圈的门禁页与实机游戏，并向腾讯客服书面确认 §2.5 对非营销、私人 playtest 链接的适用口径，结果进 `docs/spikes/`。**邀请卡是在这个现实下最稳的形态**：图片在微信里天然可传，不被链接过滤、不依赖 OG 抓取；但卡不是规避手段——卡上的二维码指向的仍是同一条链接，微信里打开它面对的是同样的规则。我们不做域名轮换、不做短链套娃。
- **公开发现承担整域风险。** 增加作品与公开过程不意味着能用产品设计消除域名拦截风险；具体处置规则与申诉渠道应在上线时复核。我们能做的是明确作者与作品说明、只收录主动公开的内容、处理举报与撤回、不在根域执行作者脚本、及时申诉；不能要求作者实名来假装解决治理，也不保证根域受影响时子域一定独立可用。
- **封禁机制与对策。** 官方可处理单链接、域名或 IP；整域处理的明文条件是「同域名下大量链接违规，经处理后仍未及时、有效整改」。对策：内容域与品牌域分开；门禁页、举报、快速下架把违规概率压低；被处理后 24 小时内提交申诉。
- **未备案的其他代价。** 朋友圈分享未备案一级域名有频次限制；微信 JS-SDK 安全域名必须备案——分享卡片只能服务端直出 Open Graph 元数据尽力而为。
- **微信内置浏览器的能力不可靠。** 门禁页用能力检测（`crossOriginIsolated`、`SharedArrayBuffer`、`navigator.gpu`、`PushManager`）而不是 UA 黑名单；首屏不依赖 WebGPU、Wasm 线程、Service Worker、全屏、横屏锁定或摄像头。
- **整个域名被墙**是存在性风险。除了内容治理和快速响应，没有技术对策。如实写在这里。
- **不落大陆。** 境内服务器要备案、要主体、要承担内容责任。香港边缘加境外主体是唯一现实路径；付费走 Stripe，支付宝经 Stripe 接境外主体。
- **登录。** GitHub 在大陆间歇可用，且不能假设每个目标用户都有账号。匿名 24 小时链接必须在任何登录之前把第一次完整跑通；GitHub OAuth 是可失败、可重试的增强路径。微信登录要开放平台企业主体，不在 v1。玩家侧的身份走邮箱与浏览器通知，不走任何需要主体的东西。

## 6. 成本与商业

**撤销的边界。** `playtest logout` 调用 `DELETE /v1/me/token`，只撤销请求携带的这一枚 API 令牌，不影响同账号其他设备，不删除作品；成功或服务端明确认定令牌失效后才清掉本机凭据，网络错误保留凭据供重试。交互先确认，自动化需 `-y`。匿名作者须先登录接管作品再退出，否则退出后失去这些匿名作品的管理入口。已经签出的隧道令牌与已建立连接仍有各自有效期，这个命令不冒充全账号紧急封禁；紧急滥用处置的全链路仍单独验收。增加这个动作是为了让 M2 的分享凭据可收回，不是新增账号体系。

**额度必须在出网前执行。** 当前单节点部署由控制面发布 `sites/<slug>/policy.json`，包含作品所属账号、档位和到期时间；创建作品、匿名归入账号及启动迁移时同步写入。边缘只读这份策略，用自己的 SQLite 持久计数，不查询控制面的库。登录账号的作品共享 UTC 自然月额度，匿名账号共享链接有效期额度；同时按作品执行每小时上限。已知长度的响应先预留全部内容字节，取消不退；未知长度响应逐块预留，WebSocket 逐块预留出网预算，额度不足即关闭流，后续请求得到明确的超限页。计数覆盖内容、封面、邀请卡、隧道与 WebSocket 的响应体，不声称等于云账单（HTTP/TLS 开销与攻击流量另计）。策略缺失、损坏或计数无法落盘时拒绝继续分发，不默默放行；控制面停止不影响已有策略。新建匿名账号最多 1 个活跃作品，免费账号最多 3 个；旧账号不强制删作品，超过上限时只禁止继续新建。为什么不用只在控制面每分钟汇总：并发、长连接和重启都会让「硬上限」变成事后数字。多节点部署须先做总预算分配，不能把本机账本复制后当作全局额度。

变动成本包括对象容量、请求、源站到边缘及边缘到体验者的传输、邮件；原件、衍生产物、历史版本、缓存未命中与未完成上传都不能漏算。供应商预算按实际区域与路径填写，参考 [S3 费用项目](https://aws.amazon.com/s3/pricing/)，不能把某一层免费出网外推成整条链路免费。游戏导出物的成本样本不能直接代表视频反复拖动与连续观看；文章的低带宽也不能掩盖长期保留的容量。

**免费档**：登录账号每月 **10 GB** 硬上限、3 个活跃 slug、保留最近 5 个版本、每 slug 并发 50、结果保留 30 天、关注不限、主动公开资格不收费；匿名链接 **1 GB / 24 小时**。到上限硬停、不产生账单。月配额之外保留每 slug 每小时流量熔断。选择硬上限是为了让一次分享不会变成作者无法控制的账单；这些数字是现有预算起点，不因别家报价或新增形态就宣称足够任何一轮使用。

这些是延续的产品额度，不是本次存储迁移顺便放宽的承诺。文章与视频先受现有大小约束，当前单文件上限为 200 MiB；原件和展示产物都计入版本体积。更大的视频档位、总物料保留预算、请求与源站读取防滥用上限须在真实 S3 路径量完后明确，不能先无限接收再补账单。到限不产生体验者付费墙，也不静默把流量转到不受控的对象直链。

**两个收钱的产品，两个购买时刻。**

1. **推广**（§3.11）——购买时刻是「我想让更多合适的人接触这一版」。沿用初始定价假设：推广 3 天 **$9**、7 天 **$19**、进本周周报 **$9**；实际交易价格在购买前明确。卖的是有标识的展示位置，不保证反馈人数、好评或粉丝增长；文章与视频的付费需求要单独验证，不把游戏测试预算当成证据。
2. **Pro**——购买时刻是「从一次分享变成持续迭代，或向客户、评审、受限群体交付」。沿用 **$15 / 月或 $150 / 年** 的定价假设：固定可改的 slug 与去角标；受控分享；180 天结果留存、版本比较、导出、3 位只读 reviewer；50 GB / 月。这里的版本比较首先是结果与说明，不是任意视频差异或源码 diff。更多流量只卖预付包（现有假设 50 GB / $10），不默认后付；存储与视频实际成本未验收前不将这些假设当成开放购买承诺。

**收款**：Stripe（信用卡 + 支付宝），要境外主体（§9）。主体落地前不收钱，两个产品在控制台里如实写「尚未开放」；「怎么活」写在 README 里——开发者对免费工具最怕的是跑路。

固定设施包括香港边缘、控制面、数据库与备份、对象存储接入、邮件服务和产品域名；「每月百美元」只能是初始预算目标，不能覆盖未经测量的媒体容量、出网与人工治理。S3 不是备份策略的代名词：备份、误删恢复、保留期限与费用必须单独验收。

## 7. 开源

不是预设，是三个问题的答案：**装它需要信任吗？** 需要，作者安装的是能从自己电脑向外发布文件或连接的程序。**代码是唯一价值吗？** 不是，托管网络、域名信誉、治理、默认值与作品的反馈和回访同样重要。**分发靠社区吗？** 是我们选择的路径：引擎、创作工具与 AI 助手通过公开协议接入，不要求作者换掉现有工具。

**怎么开**：CLI、SDK、文档 Apache-2.0；边缘与控制面 AGPL-3.0（含推广与通知的代码——收款密钥、发信密钥、滥用阈值私有，部署形态公开），附一份 `compose.yaml` 自己一台机器跑通；商标政策：fork 不能叫 playtest；安全披露渠道。引擎插件只调公开协议、不链接 AGPL 服务端库；普通自托管无需商业许可；托管版与自托管版同一核心能力，日后不抽走。

**什么时候公开**：仓库从第一天按公开的标准写，但私有开发到 v1 在真机上成立再 flip public。

**我们自己的开源计划不等于用户必须开源。** 用户选择 build in public 可以只公开作品、少量过程和更新说明；不需要把源码、提示词、原始素材或商业数据交给公众。平台也不把闭源、匿名或受控分享的作品说成不够真诚。

## 8. 交付：先收住公开试用，再完成 v1

目标仍是一个完整的创作、分享、反馈与回访产品，但当前先把已经跑通的网页闭环收成可邀请真实作者使用的公开试用切片。工程按可回退的顺序交付，不把一次定义修改变成全栈已完成。每一批都有真机记录，已上线的网页路径不为等待新形态而失效；没有验收证据的功能不得进入已支持清单。

### 8.1 当前公开试用切片

只开放一条可以端到端讲清楚的路径：作者用 CLI 发布网页目录、正在运行的本地端口，或二者组成的混合版本；拿到作品链接、二维码和按需邀请卡；体验者不登录、不安装即可进入，能自愿留名、反馈与关注；作者在控制台看到绑定版本与来源的结果，发布下一版后让愿意回来的人收到更新。广场只收录作者主动公开且经过运营者可治理的网页作品，不把自然排序、推广或陌生人流量当成试用成立的前提。

这个切片服务 §1.2 的 M1、M2、M2b、M3 与 M3c。它暂不对外声称文章、视频、合集、挑战、付费推广、Pro、Web Push 或完整 build in public 过程已经开放；这些保留为 v1 目标，不阻挡小范围网页种子作者验证核心闭环。为什么不是同时把所有已设计页面都推出去：当前最需要回答的是一条网页链接能否更快、更可信地带来具体反馈与下一版回访；扩大形态会同时引入媒体成本、版权、播放兼容和新的运营变量，反而延长这个答案。

「公开试用」不是「安全与发布链路可以将就」。开放给种子作者前，边缘事件必须只能由受信边缘写入，上传字节必须属于调用者尚未提交的预备版本，匿名身份签发必须有可解释的滥用上限，运营者下架必须同时阻断广场、直达链接、缓存和活跃隧道；下载到的 CLI 必须与当前生产 API 匹配。未满足时只能称内部测试。

### 8.2 v1 包含什么

- **CLI 与 MCP**：保留目录、端口、混合发布、终端二维码、匿名 24 小时链接、现有管理命令、按需邀请卡与机器输出；目标新增 §3.16 的文章和视频输入，明确资源范围、作品身份、真实进度与失败原因。新类型在验收前不出现在可运行帮助和能力声明中。
- **S3 物料层**：真实私有桶；权限受控的写入与读取；完整性校验；流式 / 范围读取；有界缓存；版本提交与失败对账；安全回收；已有物料迁移、回退与恢复。文件系统后端仅是本机开发或显式过渡方案，不能以模拟测试冒充 S3 验收。
- **边缘**：香港节点；泛域名证书；响应头逻辑对两条路都生效；隧道 WSS + yamux、Host 改写、WS 透传、离线页、响应体零改写；每 slug 每小时熔断；**邀请卡渲染**（竖版与横版）；**分享页**；**关注登记的转发**；根域的**广场**（左栏 + 横卡、推广位在最前、稀疏态）、**关注页**、确认与退订页；`live.json` / `plaza.json` / `capabilities.json` 三份文件的读与缓存。
- **作品邀请函与展示**：网页维持原有纯净入口；文章同页可读，视频同页点播；文案与可观察事件按形态适配；服务端 Open Graph、可选反馈与自愿关注不阻挡内容；原件、衍生展示与访问权限分清。
- **控制面**：设备授权与网页登录；slug、版本与回滚；令牌签发与撤销；用量；举报；**玩家、关注、通知队列与定时周报、发信抽象（log / resend / smtp）、Web Push**；**推广的数据模型与管理接口**（购买通道等主体）；名额与留名；公开反馈；`live.json` / `plaza.json` / `capabilities.json` 的写。
- **结果**：§3.5 的版本绑定计数、原话、来源与回访；网页 SDK 自选，阅读器与播放器只呈现实际采集的信号。没有客户端证据就没有首帧、实际时长、完读或完播的结论。
- **公开过程**：现有作品页展示作者明确选择公开的版本说明；下一版继续沿用作品身份和关注；私下反馈不追溯公开，撤回同步作用于公开快照与缓存。长过程以文章或视频作品发布，已有合集将其组织起来。
- **合集与挑战**：保留 §3.15 的创建、公开、投稿、撤回、搜索、分享、每周新作品摘要和治理；不同形态可在同一创作语境下组织，不新建动态、项目空间或个人粉丝系统。
- **控制台**（§3.13）：与广场同一个壳；作品墙与空态起点；作品页的身份栏、「现在」一行、五个分页签——结果（每版一块，数字先、句子后、来源与上版比）、点名册（有名字）、反馈（公开开关与逐条隐藏、「设为封面」）、邀请卡（竖横两张、保存 / 复制 / 分享）、设置（广场 / 名额 / 群 / 公开反馈 / 推广「尚未开放」/ 版本与回滚 / 危险区）。手机可看。
- **文档与 README**：定义目标与现有能力明确区分；体验者不登录不安装、不增加必经跳转；网页与原件不偷偷改写，衍生展示明确说明；服务端不运行用户代码；名字与公开自愿、邮箱不交作者、结果按档位留存；成本与「怎么活」如实写。

### 8.3 v1 的「完成」

- 首次网页小样本从安装到手机打开、从命令到二维码分别以 60 秒和中位 5 秒为目标，记录体积、网络与缓存条件；文章、视频单独记录实际上传及处理时间，不套用小目录承诺。普通发布不污染源目录，显式取卡才保存图片。
- Godot（线程与无线程各一）、Unity（预压缩）、Phaser、Vite 各一个真实导出物走上传路径零配置能玩，走隧道路径同样能玩；一个 socket.io 联机小游戏两台手机能对局。
- Cursor 或 Claude Code 通过 `playtest mcp` 发出一个链接，并把二维码和邀请卡贴回对话。
- 在真实 S3、真实域名上验收上传、校验、并发提交、回滚、Range、删除及垃圾回收；中断上传不产生半成品版本，复用 blob 不泄露其他作品或误删仍被引用的内容。已有作品迁移后旧链接和回滚保持可用，切换失败能退回，至少演练一次从备份恢复；本机模拟不计入这些结论。
- 一位真实作者发布带中文与本地配图的文章，另一人在手机上无需登录和额外跳转即可阅读全文、留下版本绑定反馈；缺图、超限、危险内容和权限撤回有正确失败形态，原件不被渲染器覆写。
- 一位真实作者发布基线编码视频，另一人在真实 iOS / Android 浏览器上点播、暂停、拖动，验证 Range、计量与弱网失败恢复；不支持的编码和超限在提交前说明，页面打开与实际播放分开记。
- 一张邀请卡在微信群里发出去，另一个人长按识别二维码进到门禁页、点「开始」、音频能播（Chrome / Safari / 微信各验一次），点名册上显示「来自邀请卡」。
- 一个玩家在门禁页留名并关注；开发者发第二版；玩家收到邮件（或浏览器通知），点进去，点名册上显示「来自通知」并标为回头的人。
- 网页、文章、视频各走一次真实的「发布 → 分享 → 具体反馈 → 下一版 → 自愿关注者收到更新并回访」。作者可选择公开前后两版说明，也能撤回；没有公开的草稿、反馈与原件不因历史展示或旧通知泄露。把同一次创作的文章与原型放进合集，不改变彼此的版本与权限。
- 一个玩家在广场关注广场；周一收到周报；周报里的作品点开就玩。
- 广场上一张推广位（运营者赠送）显示为「推广」，免费流顺序不受影响。
- 控制面停掉、S3 可用时，已有且仍被授权的作品与公开页面能读；反馈与关注不冒充保存成功。S3 失联时分别验收缓存命中、冷读取与权限无法确认的失败形态；恢复后只有已确认接收的任务才重试，不重复发信或发布旧指针。

### 8.4 发布阻断

**当前公开试用切片的阻断：**

- 本工作树已经为边缘事件入口加入部署凭据、为匿名身份加入持久化平台保险丝、把 blob 绑定到调用者一小时内的待提交清单；但它们尚未部署到生产并用生产配置复验。生产仍运行旧镜像，或边缘与控制面的凭据没有同时轮换成功时，只能内部测试。
- 运营者下架不能阻断作品直达地址、缓存、已签发隧道令牌与活跃连接，或没有留下一次完整处置演练，不开放陌生人可访问的公开收录。
- 当前源码、生产 API、CLI 版本和公开下载物不对应；主分支尚未推送、版本 tag 不在待发布提交上、发布产物未经过工作流校验，不能把旧二进制当成当前入口。
- 真实手机和微信路径、Gmail / QQ / 163 收件箱往返没有日期记录时，分别只声称浏览器路径或服务商接受请求，不声称微信可达或邮件已送达。

**完整 v1 的阻断：**

- S3 没有真实桶记录、已有数据未校验、回退 / 恢复未演练，不宣称已完成生产迁移，也不删除旧盘数据。
- 某种形态没有独立的真实作者、手机、反馈、版本、权限、限额与故障记录，不开放为已支持能力。只上传了 `.mp4` / `.md`、本地页面能显示或桌面模拟通过都不算完成。
- 原件字节被偷偷改写、根域能执行作者脚本、私有物料或公开过程撤回后仍可绕过权限、登录 / 安装 / 新的必经跳转挡住首次体验，阻断对应能力上线。
- 真实微信账号在 Android ≥ 6 台、iOS ≥ 4 个系统版本上，私聊 / 群聊 / 朋友圈打开门禁页并进入游戏；邀请卡在群里长按识别的成功率；腾讯对外链规范 §2.5 适用口径的书面答复。
- 香港边缘三网晚高峰一周压测记录。
- 发信域名的 SPF / DKIM / DMARC 通过，测试信在 Gmail、QQ 邮箱、163 不进垃圾箱。

| --- | --- |
| 按形态、体积与入口拆开的首次发布耗时；从命令到可访问链接的时间 | 供给侧摩擦，不把视频上传和小网页缓存命中混成一个数字 |
| 发布后邀请卡被保存 / 分享的比例；来源为「邀请卡」的打开占比 | 邀请环 |
| 接触作品后自愿反馈、留名与关注的情况，按形态分开 | 体验者愿不愿意留下，不把它们变成必填任务 |
| 从分享到第一条作者认为有用的具体反馈的时间 | M3 的价值；初期由作者人工说明哪条有帮助，不用 AI 分数替代 |
| 作者再次发布的情况；下一版的回访会话与通知来源 | M3c 与公开创作是否连续，打开人数不冒充认证真人 |
| 作者公开的版本说明是否帮助后来者理解变化；是否在下一版说明如何处理问题 | M3d 的连续性；用实际访谈与作者原话，不自动宣称反馈导致改动 |
| 关注广场与合集的数量；摘要实际投递与带来的访问；同合集跨作品体验 | 注意力环；不加追踪像素，也不伪造未采集的周报打开率 |
| 公开作品里带封面的比例；每周新公开的作品数 | 广场好不好看、有没有东西 |
| 资源失败；有客户端证据时的加载 / 播放失败与就绪情况 | 展示是否可信，不凭页面请求推断首帧、完读或完播 |
| 反馈数与实际来源；作者发布下一版前是否回看反馈 | 结果层有没有被用，不以格式数量、观看时长或日更天数代替 |
| 每形态的原件与历史容量、请求、回源与出网成本、超限次数 | S3 与视频的成本边界是否成立 |
| 推广售出天数；推广带来的打开 | 有没有东西可卖 |
| 举报数、撤下数、申诉数；退订率与投诉率 | 治理与发信信誉 |

阶段目标优先是每种已开放形态都出现真实的反馈与下一版回访，且成本、失败与权限可解释。社群规模、每周供给与回访数量可设运营目标，但不把网页游戏目标直接复制给文章和视频，也不以「build in public」口号或支持扩展名的数量证明产品成立。

## 9. 只有创始人能拍板的事

以下记录当前选择与理由，不按日期维护决定流水账，历史在 git。

| 选择 | 为什么不是另一个 |
| --- | --- |
| 服务以作品为中心的 build in public，包含独立文章、视频与网页 | 只做游戏会错过同一类分享、反馈与迭代时刻；泛内容平台则把目标换成曝光与消费。边界按时刻，不按「必须能玩」 |
| 作品、版本、反馈、关注、合集是积累单位，不先做个人动态或粉丝系统 | 作者已经有创作工具与社群；再经营一套人设不是得到具体反馈的前提。已有对象能承接 M3c / M3d |
| 公开是一种选择，不是准入门槛 | 强制公开源码、草稿、收入或反馈会把公开创作变成额外负担，也会泄露作者未打算分享的东西 |
| S3 作为生产物料主存储，边缘继续负责交付与额度，关系库保留 | 共享本地目录限制媒体与版本积累；公共桶直链绕过产品控制；把业务关系也塞进对象存储不能缩短用户时刻 |
| 三种有限形态共用发布闭环，按批验收 | 一次支持任意格式会把团队变成编辑器和媒体处理平台；只接受文件但不能阅读、播放、反馈也不算交付 |
| 努力带来合适的人，如实报告结果，不保证流量或认可 | 单卖链接解不了「没有观众」，保证人数和好评又超出可控范围。广场与合集是运营责任，不是增长承诺 |

**继续保留的约束**：Rust 与现有工作区；上传、隧道与混合交付；匿名首次分享；平台根域不执行作者脚本、作品使用独立源；原件不偷偷改写；服务端不运行用户代码；硬额度与每小时熔断；可选身份与反馈。品牌仍用 playtest，不因多形态急着改名或改域。

**上线前必须确认的外部条件**（是否完成以实际配置和真机记录为准，不用本文代替状态检查）：

1. **S3 后端、区域、访问凭据与预算**：生产切换、旧数据校验、备份与恢复需要真实环境；密钥不进仓库，不靠修改定义自动开通。
2. **邮件服务与 DNS、长期作者身份入口**：发信域验证、真实投递、GitHub 登录失败兜底；本机 `log` 只算预览，不算把人带回来了。非技术作者的身份与发布摩擦另行观察。
3. **境外主体、收款与专业合规意见**：决定推广与 Pro 何时开放；媒体版权、隐私、内容治理与收费问题不能由产品文案保证。
4. **真实种子作者与运营投入**：分别找到愿意发网页、文章、视频的人，走到反馈和下一版；组织已有合集 / 挑战，不向生产灌假作品或数字。
5. **真实网络与设备**：香港边缘及对象源路径、三网晚高峰、手机阅读与视频播放、微信分享能力分别留证，不把地理标签当延迟与可达性证明。

## 10. 维护纪律

- 本文是唯一产品定义，方向变了直接重写，不留 changelog；每个结论要能回答「为什么不是另一个」。
- `docs/spikes/` 放真机记录，只增不改；本文里任何一句「已验证」都要能指到一条 spike。
- 新增的名词、页面、命令参数、依赖，必须让 §1.2 的某一个时刻更短或更可信；属于三个环或打着 build in public 的名字本身不构成准入理由。
- 不从其它项目搬代码；借鉴的是想法，用自己的话重写。
- 做不到的地方在界面和文档里明说，不用「已支持」盖过去；等外部依赖的功能写「尚未开放」，不放不能点的按钮。
- 新作品类型与 S3 迁移分别验收：文章不是一个 Markdown 文件上传成功，视频不是一个 MP4 对象写入成功，生产迁移不是抽象接口或本机模拟通过。未验收的目标不能进入 CLI / MCP 的能力声明。
- 全站只使用 playtest.run 品牌与账号；平台权限不进入作品运行子域，公开体验不需要登录。
