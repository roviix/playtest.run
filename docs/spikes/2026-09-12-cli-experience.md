## 要回答的问题

M1 / M2 第一次发布是否必须先理解所有维护命令？M3 回到已发布目录后，是否还要抄作品标识？错误选项会不会让开发者误以为操作已生效？

选择减少首次展示、复用当前目录记录和提前拒绝无效选项，而不是新建命令分组或重命名全部子命令。产品约定见 DESIGN §3.2。

## 本机真实二进制

运行本次源码构建的 `target/debug/playtest`。使用临时目录与隔离 HOME，API 指向 `http://127.0.0.1:1`，不使用开发者真实令牌、不操作线上作品。

| 操作 | 实际结果 |
| --- | --- |
| `playtest -h` | 17 行快速开始，展示目录、端口、更新、招募和常用后续动作；引导到 `--help` |
| `playtest --help` | 完整命令与参数，发布信息、邀请与招募、输出、运行设置、脚本与连接分组；不暴露旧参数合并的内部历史 |
| `playtest card --help` | 目标可省略，默认 `.`；保留输出路径及全局 API / JSON 选项 |
| `playtest --name demo` | 提示缺少目录或端口，退出码 2，不再显示帮助后成功退出 |
| `playtest 5173 --public --json` | 一个 `usage` JSON 错误，退出码 2，提示改用目录发布；没有先尝试连接本地服务 |
| `playtest card --json`（未发布目录） | 一个 `bad_input` JSON 错误，退出码 6，提示先发布当前目录，不猜最近作品 |
| `playtest --api http://127.0.0.1:1 ls --json`（无身份） | 空作品列表，退出码 0；全局 API 不再被当作发布参数冲突 |
