## 本轮收敛

- 当前切片只承诺网页目录、本地端口和混合发布，以及链接／二维码／邀请卡、免登录试玩、留名、反馈、关注、作者回看结果和下一版回访。文章、视频、合集、挑战、付费推广、Pro、Web Push 和完整 build in public 仍是 v1 目标，不再混成这次开放的前置范围。
- README 明确源码版本、私有仓库和旧 Release 的边界；CLI 候选版本统一为 `0.3.0`。发布闸门新增当前 tag 必须指向 HEAD、`origin/main` 必须一致、仓库可公开读取、五个平台产物与 `SHA256SUMS` 必须齐全的检查。
- 控制台与广场发布弹窗保留三种入口，但示例只使用当前 CLI 能解析的 `playtest ./dist`、`playtest 3000` 和 `playtest ./dist --backend 8000`；默认不擅自公开到广场。文档契约检查现在也解析这三条命令，不只数 UI 项目。

## 本地关闭的三个写入口风险

1. 边缘批量事件改为携带 `Authorization: Bearer` 部署凭据；API 无凭据、错凭据或未配置时均拒绝，内部路由不再提供浏览器 CORS 预检。edge 配了控制面地址却没配凭据时拒绝启动，API 与 edge 都拒绝短于 32 字节的值。凭据只在环境变量和请求头里，不进 URL 或事件日志。
2. blob 写入必须命中同一作者尚未提交、且一小时内创建的 prepare 清单，同时校验声明大小与实际大小。每位作者最多同时保留 8 份准备记录；过期记录在 prepare 和 blob 授权路径都会清理。没有准备、别人的准备、过期准备、哈希或大小不符都不会落成 blob。
3. 匿名身份签发增加 SQLite 持久化的全平台每分钟 60 次保险丝。这只是单节点平台熔断，不是逐 IP / 逐来源反滥用；接入可信代理来源后的细分限制仍未完成。

## 仍然阻断公开试用

`bash scripts/check-release.sh` 的只读结果是 5 项自动阻断：工作树未固定到提交、没有 `v0.3.0`、`origin/main` 不是当前 HEAD、仓库仍私有、没有带五个平台产物和校验文件的 `v0.3.0` Release。六个生产开发者端点当时均返回 200，但这不能证明当前工作树已上线。

在解除以上五项之前，还必须：

- 把新的 edge/API 共享凭据随候选镜像一起部署并轮换，验证错误凭据确实 401，且事件正常续传；不能只改本地 Compose。
- 设计并验收运营者“全链路暂停”：广场、根域邀请函、作品直达、缓存、已签发隧道令牌和活跃连接同时失效，并留下一次恢复演练。现有 `hide` 只撤下广场和推广，作品链接照常能开。
- 在真实 iOS / Android 与微信里走邀请卡、门禁、开始、音频和反馈；在 Gmail、QQ、163 走确认、更新与退订；按 DESIGN 记录条件和失败。
- 为匿名签发叠加可信的逐来源限制，或用部署层等效控制证明平台保险丝不会被单一来源耗尽；完成备份异机恢复与三网晚高峰记录。

因此，本轮结论是“本地候选已明显收敛、可以进入部署与真机验收”，不是“已经可以公开发布”。
