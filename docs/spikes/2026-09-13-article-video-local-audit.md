# 2026-09-13 · 文章与视频本机实现核对

## 结论

本轮把 DESIGN §3.16 的文章与视频契约接进了共享模型、CLI、上传 API、玩家边缘入口和控制台，并用本机自动化测试覆盖了主要成功与失败路径。

这份记录**不是真机记录，也不代表文章或视频已经对外支持**。本轮没有把当前工作树部署到生产，没有在 iPhone、Android 或微信里打开链接，也没有用真实外网对象存储完成一次 CLI 发布。因此帮助、MCP 示例和公开文档仍不把单文件发布当成已经可用的能力。

## 本轮实现

- `playtest article.md` 只收一份 UTF-8 Markdown 与正文显式引用的本地 PNG、JPEG、WebP 或 GIF。第一条一级标题是默认标题；没有一级标题时才使用文件名。原生 HTML、远程／data 图片、越界路径、本地文件链接和危险协议会在联网前拒绝。
- API 不信任扩展名或 CLI 的预检：提交文章时重新读取源文件、比对显式图片集合和真实图片格式，生成独立的安全 HTML artifact。玩家入口只读 artifact，原始 `.md` 不从作品域公开。
- `playtest video.mp4` 要求一个真实 MP4，至少有一条 H.264 视频轨；存在音轨时，每条音轨必须是 AAC。CLI 和 API 都解析容器，不把 `.mp4` 后缀当证明；API 用临时文件流式检查并在失败后清理。
- 作品类型写进站点、版本清单、广场和 API 合约。同一作品的新版本不能从网页、文章、视频之间偷偷换类型，需要显式发布成新作品。
- 文章正文直接留在根域邀请页；视频使用带 `controls`、`playsinline`、无 `autoplay` 的原生播放器。媒体仍经过 edge 的配额、访问和单段 Range 路径，不另造公开对象地址。
- 文章／视频打开也取得根域 `pt_sid`，使 `gate_view` 可以按会话去重。控制台只展示能证明的“打开、回来、反馈”，不把打开文章说成读完，也不把打开视频说成已经播放。
- 玩家、通知、邀请卡、广场和控制台按作品类型使用“读文章／看视频／试玩”“读者／观众／玩家”，不再把所有内容都叫游戏。

## 本机自动化结果

以下命令在 2026-09-13 当前工作树串行运行：

- `cargo check --workspace --all-targets`：通过。
- `cargo test -p playtest-common`：94 项单元测试与 11 项 avatar 集成测试通过，0 失败。
- `cargo test -p playtest-api --test upload_flow --test email_templates`：上传流 23 项、邮件模板 7 项通过，0 失败。上传流包含文章 artifact、作品类型稳定性和伪 MP4 拒绝。
- `cargo test -p playtest-edge --lib --test serving`：190 项单元测试、32 项 serving 集成测试通过，0 失败。serving 包含文章源文件不可见、正文图片同源、视频无自动播放和 Range 响应。
- `cargo test -p playtest --bin playtest`：CLI 145 项通过，0 失败。包含 Markdown 只收显式资源和原生 HTML 在联网前拒绝。
- `cargo fmt --all -- --check`：通过。
- 控制台 `npm run build`：通过；最终 CSS 50.79 kB（gzip 10.88 kB），JS 105.99 kB（gzip 35.80 kB）。

曾尝试 `cargo test --workspace`，并行链接在本机只剩约 166 MiB 时因 `No space left on device` 中止；没有观察到测试断言失败。清除 8.0 GiB Rust 构建缓存后，改用以上相关测试目标串行复核。这是资源限制，不被记成全工作区测试通过。

## 真机验收仍缺

在出现以下追加记录之前，CLI 的运行时提示必须继续明说文章／视频只完成实现核对，不能写“已支持”或“已验证”：

1. 从真实开发者电脑通过已部署 API 和对象存储，各发布一篇带中文文件名与多张图片的文章，以及一段真实 H.264/AAC MP4；记录失败重试、更新、回滚与删除。
2. 在 iPhone Safari、Android Chrome 和微信内置浏览器检查文章首屏、长文滚动、图片、链接与反馈返回路径；确认玩家不登录、不安装、不多跳一次。
3. 在同三种环境检查视频首帧、手动播放、暂停、拖动、横竖屏、静音／有声文件、弱网恢复和 Range；不能只凭 HTTP 206 推断真机可播。
4. 从分享链接走到作者控制台，核对文章／视频只产生当前能证明的统计，且邀请卡、邮件和反馈称谓一致。

结论只能写成“文章与视频的本机端到端实现已进入真机验收”，不能写成“文章与视频发布已经上线”。
